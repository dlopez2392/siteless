<objective>
Lift the working Socrata client out of `scripts/refresh-outlet-counts.ts` into
`src/lib/socrata/`, add the two dataset row schemas and their pure transforms, and record the
msw fixtures CI replays.

Purpose: DATA-01. The counts script already encodes four things it cost real time to learn —
SoQL quoting, half-open NAICS ranges, the `000` statewide sentinel, and the fact that
`outlet_naics_code` is a Socrata `number` so a string-prefix predicate returns HTTP 400
`query.soql.type-mismatch`. 03-RESEARCH is explicit: **lift it, do not rewrite it.**

🔴 The single most expensive correction in this phase lives here. `3kx8-uryv` is **not** "the
out-of-business dataset" its nickname claims. It is *All Permitted Sales Tax Locations and
Local Sales Tax Responsibility*, 1,452,890 rows, with different column names
(`tp_number`/`loc_number`/`loc_name`/`loc_county`), a nullable `out_of_business_date`, and
🔴 **UNPADDED county codes**: `loc_county = '031'` returns **0 rows**, `loc_county = '31'`
returns **21,062**. Querying it with `jrea-zgmq`'s padded RGV list returns 37,875 rows instead
of 58,937 — a plausible-looking number that is 36 % short. D-03's *intent* survives intact;
its stated field names and code format do not. This plan makes the divergence explicit in code
and in a test so nobody later "fixes" it back to the CONTEXT wording.

Output: `src/lib/socrata/{client,permits,closures}.ts`, three msw fixtures, the tests, and the
optional `SOCRATA_APP_TOKEN` in `src/env.ts`.

Paging, from the measurements: `$limit=50000` plus a **mandatory** `$order` plus an `$offset`

across pages**, so refuse to run without one (throw if `params.$order` is absent).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| data.texas.gov → `src/lib/socrata/` | An untrusted third-party JSON payload crosses into our type system |
| seeded county codes / NAICS ranges → SoQL `$where` | String assembly into a query language |
| CI → the public internet | Must not be crossable at all |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-03 | Tampering | `permitRowSchema` / `closureRowSchema` | mitigate | `zod` bounds type and length on every field before a value reaches the driver; the schemas name exactly the fields we read so the payload's other columns are stripped, not inherited |
| T-3-04 | Tampering | `socrataQuery` `$where` | mitigate | The `$where` is assembled from **seeded** county codes and NAICS ranges only; `quote()` doubles an embedded `'`. No caller input reaches SoQL in this phase, and a test asserts the county-code constants are literals |
| T-3-05 | Tampering (SSRF) | `SOCRATA_HOST` | mitigate | One module-level constant host; `dataset` is interpolated into the path from a fixed dataset-id literal in `permits.ts`/`closures.ts`, never from caller input |
| T-3-14 | Information disclosure | msw harness | mitigate | `onUnhandledRequest: 'error'` stays in one place; the repo-wide network grep gate ships in 03-06 and names `data.texas.gov` |
| T-3-02 | Repudiation | `SOCRATA_APP_TOKEN` | accept | Optional, server-only, never `NEXT_PUBLIC_`; absent today and the client works without it |
</threat_model>
