<objective>
Ship the normalization module (DEDUP-04, D-12) as pure, unit-tested TypeScript, and the two
grep gates that keep it authoritative.

Purpose: 🔴 **`unaccent()` is STABLE, not IMMUTABLE.** Measured on the real local PostgreSQL
18.6: both a generated column and an expression index were refused with `42P17`
(`select provolatile from pg_proc where proname='unaccent'` returns `s`, because the dictionary
file can be reloaded). That settles "which side is authoritative" by a refusal, not a
preference: `name_norm`, `phone_e164`, `street_num`, `street_norm` and `postal` are **plain
columns written by TypeScript**, and SQL never normalizes — the only SQL that touches a
normalized value is `similarity()`, `=` and `%`, all over already-stored values.

And the two pipelines genuinely disagree, so this is a correctness rule rather than a style
choice: `unaccent` maps `ø→o`, `æ→ae`, `ß→ss`, `œ→oe`, `Ł→L`, `đ→d`, `ı→i`, while NFD +
strip-combining-marks leaves all of them unchanged. For Spanish they agree; for the Latin-1
ligature/stroke set they do not, and a blocker and a scorer that disagree about a key produce
candidate pairs that vanish when re-scored.

🔴 The common workaround — `create function app_name_norm(text) … immutable` wrapping the
STABLE `unaccent` — is **forbidden**. Postgres accepts the declaration and does not verify it;
it is a lie to the planner, it puts the index at the mercy of `unaccent.rules`, and it
re-creates the two-implementations problem this module exists to close.

Output: four normalize modules, three test files including the M24 grep gate and the CI-network
gate.
</objective>

`src/lib/normalize/name.ts` — pure, no I/O, no database:

```ts
const LIGATURES: Record<string, string> = {
  'æ':'ae','Æ':'ae','œ':'oe','Œ':'oe','ß':'ss','ø':'o','Ø':'o',
  'đ':'d','Đ':'d','ł':'l','Ł':'l','ı':'i','ð':'d','þ':'th',
};
const LEGAL = new Set(['llc','l','c','inc','co','ltd','corp','dba','lp','llp','pllc','plc','incorporated','company','corporation']);
const STOP  = new Set(['el','la','los','las','de','del','y','and','the','of']);
const TRADE = new Set(['taqueria','carniceria','panaderia']);
```

Pipeline, in this order: ligature fold → `normalize('NFD')` → `replace(/\p{M}+/gu, '')` →
`toLowerCase()` → `replace(/[^a-z0-9]+/g, ' ')` → **split into tokens** → filter out `LEGAL`,
`STOP` and `TRADE` → rejoin with a single space → `trim()` → `null` when empty.

🔴 Three defects the SQL prototype exhibited on real RGV rows, each of which deserves its own
unit test and each of which the token pipeline avoids:

1. **A regex stopword strip leaves a leading space.** `"La Taqueria De Guanajuato"` normalized
   to `" taqueria guanajuato"` — a leading space changes every leading trigram and silently
   lowers similarity. **Tokenise, filter, re-join; never regex-replace in place.** `trim()` is
   load-bearing.
2. **Adjacent stopwords survive a regex.** `(^| )(el|la|…)( |$)` consumes the shared space, so
   `"de la"` loses only one word. A token filter removes both.
3. **Digits leak in from the source.** Do **not** strip digits — `"Taqueria Las 3 Torres"` needs
   its `3` and `"3 Amigos"` is a real name — but **do** strip a *trailing* token that is a
   10- or 11-digit run, and return `hadStoreNumber: true` when a trailing all-digit token was
   removed, so the scorer can forgive `"SMARTSTYLE 8"` vs `"Smartstyle"`.

Export `nameNorm(raw): string | null` and `nameNormDetail(raw): { norm: string | null; hadStoreNumber: boolean }`.

`src/lib/normalize/phone.ts`:

```ts
import { parsePhoneNumberFromString } from 'libphonenumber-js';
export const TOLL_FREE_NPAS = new Set(['800','833','844','855','866','877','888']);
export function phoneE164(raw: string | null | undefined): { e164: string | null; blockable: boolean }
```

Parse with region `'US'`; reject when not valid, when `country !== 'US'`, when the national
number is not 10 digits, or when the NXX is `555` (D-12). Return
`{ e164: p.number, blockable: !TOLL_FREE_NPAS.has(npa) }`.

🔴 `e164` is stored and displayed; **`blockable` is what the phone blocking key and the D-07
trusted-identifier rule read.** Storing a toll-free number is correct — danlo may still want to
dial it — blocking on it is not. Measured: one toll-free number is shared by **215** Overture
places, giving a 23,005-pair block from a single row; excluding the seven toll-free NPAs drops
the worst block to **32** and the phone-block pair count from 61,677 to 12,717. Record those
numbers in the module header.

🔴 Overture `phones[]` is raw, which is why `libphonenumber-js` and not a digit regex: measured
40,127 `+1…`, 6,403 bare 10-digit, 2,581 bare 11-digit and **2,263 "other"** (extensions,
international, junk) — and the same toll-free number appears in two of those forms.

`src/lib/normalize/index.ts` re-exports all three modules.
