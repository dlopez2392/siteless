<objective>
Build `/sources` — the run ledger that makes success criterion 1 visible (D-06, D-17).

Purpose: "It reads like a ledger" (danlo's own words): source · version ingested · last run ·
added / changed / unchanged / gone. The focal point is **the four count columns as a block** —
the eye lands on the leftmost source name and travels right, and those are the only
`tabular-nums` on the screen, right-aligned on desk so the digits line up into a column that can
be read down as well as across. **That alignment is the design; nothing on this screen is
accent.**

🔴 **UI-SPEC Executor Rule 27: the four source rows render before any run exists.** They are
static structure, not data. A screen that shows nothing until an ingest has run cannot tell you
that an ingest has not run.

🔴 **No chart library.** The confidence distribution is composed from `Progress` and painted
divs. `recharts` does not enter the bundle in this phase either.

Output: the route, four components, the extended tone map.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `ingest_runs.stats` (jsonb) → the screen | Data written by a desk script is rendered as counts and band bars |
| `ingest_runs.error` → the screen | An error string from a third-party feed is displayed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-09 | Information disclosure | `/sources` | mitigate | `requireOrg()` in the layout, `withOrg` + `orgPolicies` on `ingest_runs`; a tenant sees only its own runs |
| T-3-03 | Tampering | rendering `stats` and `error` | mitigate | React escapes text by default and no component uses `dangerouslySetInnerHTML`; the band bars read numbers through `Number()` with a clamp, so a malformed `stats` cannot produce a negative width |
| T-3-11 | Information disclosure | the ledger | mitigate | The ledger renders counts and versions only — no business row, no `name_norm`, no `internal_notes` |
| T-3-14 | Information disclosure | licence compliance | mitigate | The attribution block is the CDLA-Permissive 2.0 and public-domain notice the sources require, and it states plainly that no Google data is in the durable record |
</threat_model>
