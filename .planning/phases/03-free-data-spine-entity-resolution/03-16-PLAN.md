<objective>
Build `/review` — the 80–95 band worked to zero, one pair at a time, from a phone (D-13, D-15,
D-16).

Purpose: DEDUP-01's human half. The focal point is **the candidate pair** — the two
`display_name`s at Heading 20/600, one per side — because that is the only thing a human can
actually adjudicate. Everything else supports that judgement: the remaining count and the score
are deliberately quiet and never larger than a name.

🔴 **UI-SPEC Executor Rule 20: never advance the queue before the decision is recorded.** The
pressed button enters a busy state and the pair advances only on a successful write. Optimistic
advance with a failure toast is Phase 7's undo pattern (TRI-02) and is explicitly **not** built
here — a silently dropped decision is invisible, and the whole value of this queue is that every
pair got a human answer.

🔴 **This is the shape TRI-03 reuses in Phase 7.** Do not invent a second one there.

Output: the route and five components.
</objective>

the screen's single primary CTA, `data-testid="review-action-same"`), **"Different"** (outline,
`review-action-different"`), **"Skip"** (ghost, `review-action-skip"`).

Phone: **two rows** — row 1 "Same business" full width, 48px tall; row 2 "Different" and "Skip",
48px tall, 8px gap, equal width. Three 16px labels do not fit a 390px row and dropping button
text to 14px would break the type contract. Desk: one 44px row, left-aligned.

🔴 **`onClick` inside `useTransition`, never `<form action>`.** React resets a form even when the
action **failed**, and a Radix control driven by that reset walks its state backwards.

```tsx
const decide = useCallback((decision: 'merged' | 'distinct' | 'skip') => {
  setError(null);
  startTransition(async () => {
    const result = await recordReviewDecision({ candidateId, decision });
    if (!result.ok) { setError(result.message); return; }   // 🔴 do NOT advance
    toast(TOAST_FOR[decision]);
    router.refresh();                                        // the server re-reads the next pair
  });
}, [candidateId, router]);
```

🔴 **Executor Rule 20.** The pressed button shows `Spinner` + "Recording…", **stays 48px and does
not resize**, and the other two go `aria-disabled`. **The pair stays on screen until the decision
is recorded.** No optimistic advance, no undo toast (TRI-02 is Phase 7), no swipe gesture
(MOB-02 is Phase 7 — `motion`'s `drag` prop does not appear on this screen).

🔴 **Toast on success only; a refusal is a persistent `Alert`** — "a toast that has been
dismissed is indistinguishable from one that never fired". The refusal copy is UI-SPEC's:
*"That decision didn't reach the server. Nothing was recorded and this pair is still pending, so
you haven't lost your place in the queue."* with "Try again" and "Reload the queue".

🔴 **Executor Rule 23: neither "Same business" nor "Different" gets a confirmation.** Nothing is
deleted by either; the reversal is Unmerge on the detail view (D-20). A confirmation on a queue
worked from a phone would double every tap. This is also what keeps "nothing destructive and
nothing irreversible sits in the thumb zone" true.

**Focus and announcement:** after a recorded decision, move focus to the new pair's first heading
(`tabindex={-1}`), and keep the remaining count inside the `aria-live="polite"` region so the new
count — and the "Queue clear" end state — are announced, not merely rendered.

**Motion:** the queue advance is 150 ms — the decided pair exits opacity 1→0 with an 8px upward
translate, the next enters 0→1, and the new pair is **mounted before the old one is removed** so
the region is never empty. 🔴 `prefers-reduced-motion`: use `useReducedMotion()` **plus** the
media query and **disable the animation, never the content** — durations to 0, transforms
dropped, the next pair appears immediately at its final state. There is no code path in which a
reduced-motion user sees an empty queue region (recorded 956 Woodworks defect: a naive rule
blanked the hero).
