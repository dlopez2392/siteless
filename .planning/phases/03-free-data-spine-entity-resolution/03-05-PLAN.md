Create the five new spine tables, extend `businesses` and `source_records`, and ship the one
`db:custom` migration that carries everything drizzle-kit's differ cannot emit — the CHECK
swap, the three new composite provenance FKs, the six blocking indexes, the explicit DML
grants, the trigger attachments and the table comments that record what deliberately has no
`log_event`.

Purpose: DATA-03 (per-field provenance, durable cites durable), DATA-04 (the idempotent upsert
needs its unique index), DEDUP-01/02/03 (the candidate, merge and alias tables, and the
external key's uniqueness and shape). Every new table owes four things in its **creating**
migration: `org_id`, RLS with at least one policy, **explicit DML grants**, and a row in
`TENANT_TABLES`. `drizzle/0013_reference_policies_and_grants.sql` is the single migration that
does all four — it is the template.

🔴 This is the only plan in the phase that writes a schema migration. Build and type checks
pass **without** applying it — types come from the TS schema, not the live database — which is
exactly the false-positive verification state the apply step exists to prevent.

Output: five new schema modules, two modified, two migrations, three widened test lists.
