<objective>
Ship the US Census **batch** geocoder client (D-08) beside the existing one-line client, with
the three parser defects the live probes exposed already encoded.

Purpose: D-08 makes Comptroller outlet addresses batch-geocoded at ingest, which is what lets
the geo gate, the distance feature, the 25 km rule and Phase 2's radius presets reach
Comptroller-only businesses. The endpoint is free, federal and keyless — the same D-02 choice
Phase 2 made, now the batch endpoint.

Three measured facts break a naive parser, and all three were reproduced live on 2026-09-22
against real RGV addresses:

1. 🔴 **The response is ragged.** A `Match` line has 8 fields, a `No_Match` line has **4**, and
   a `Tie` line has **3**. A parser that indexes position 6 unconditionally reads `undefined`;
   one that asserts a column count throws on ~29 % of rows.
2. 🔴 **Result order is NOT input order.** Measured at n=1,000 and n=3,000 — the 3,000-row
   response began `"1462", "2793", "1461"`. **Rejoin on the ID column; never zip by position.**
3. 🔴 **Column 6 is `"longitude,latitude"`** — `"-97.672649743751,26.189604634647"` for
   Harlingen. Longitude first, matching the axis-order pin `src/lib/geocode/census.ts` already
   documents for the one-line endpoint.

Sizing the plan must honour: ~**70.9 %** match rate (measured twice, n=1,000 and n=3,000), so
≈ **10,100 of 34,928** RGV Comptroller outlets will have **no location** and fall to text-only
matching — D-10 then caps every one of their pairs at the review band.

Output: `src/lib/geocode/census-batch.ts`, five recorded fixtures, the tests.
</objective>

Create `src/lib/geocode/census-batch.ts` beside the existing one-line client.

Hard-coded host and path (T-3-05: no caller-supplied value ever reaches the host or the path):

```ts
const CENSUS_HOST = 'https://geocoding.geo.census.gov';
const CENSUS_BATCH_PATH = '/geocoder/locations/addressbatch';
const CENSUS_BENCHMARK = 'Public_AR_Current';
export const CENSUS_BATCH_CHUNK = 1000;   // 26 s measured. 10,000 would be a 5.2-minute held-open request.
```

🔴 **Use `locations/addressbatch`, not `geographies`.** The county FIPS is already known from
`outlet_county_code`, and `geographies` measured ~**9× slower** (4,448 ms vs 488 ms for the same
8 rows).

Result union — never throws, every outcome a named reason (the same shape `census.ts` uses,
plus two new ones):

```ts
export type BatchOutcome =
  | { kind: 'Match'; matchType: 'Exact' | 'Non_Exact'; matchedAddress: string; lat: number; lng: number }
  | { kind: 'No_Match' }
  | { kind: 'Tie' }
  | { kind: 'ChunkFailed'; reason: 'unreachable' | 'bad_shape' | 'count_mismatch' };
```

`parseBatchLine(line: string): { id: string } & BatchOutcome`:

```ts
const f = parseQuotedCsvLine(line);
const id = f[0];                                  // 🔴 rejoin on the ID — order is NOT input order
if (f[2] !== 'Match') return { id, kind: f[2] as 'No_Match' | 'Tie' };   // branch BEFORE reading f[5]
const [lng, lat] = f[5].split(',').map(Number);   // 🔴 LONGITUDE FIRST
return { id, kind: 'Match', matchType: f[3] as 'Exact' | 'Non_Exact', matchedAddress: f[4], lat, lng };
```

🔴 Copy the axis-order comment from `census.ts` verbatim in spirit: *`x` is LONGITUDE and `y`
is LATITUDE; the Census Geocoder does not return `(lat, lng)`, and reading these in written
order puts every RGV point in the Indian Ocean.* Assert the sign, not the presence.

`geocodeBatch(rows, opts)`:

- chunk at `CENSUS_BATCH_CHUNK`, run **3 chunks concurrently** with `p-limit` (35k rows in
  ~6–8 minutes at the measured ~32 addr/s)
- build the CSV with `id, street, city, 'TX', zip.slice(0,5)`, quoting every field
- **Retry policy:** the service returns `200` for everything including total failure, so retry
  on a transport error, on a non-200, **or on a response whose line count ≠ the request's row
  count**. Exponential backoff 2 s / 8 s / 30 s, three attempts, then record the chunk as
  `ChunkFailed` in the returned map and in the caller's run report. No budget is at stake — it
  is free.
- return `Map<string, BatchOutcome>` keyed by the input id

🔴 **`Non_Exact` can flip a direction.** Measured: `100 E CANO ST` → `100 W CANO ST`;
`500 N CLOSNER BLVD` → `500 S CLOSNER BLVD`; `717 N 77 SUNSHINESTRIP` → `717 S 77 SUNSHINE
STRIP`. **Store the match type** and treat `Non_Exact` as location-only evidence: it may feed
the distance feature but must never be promoted to the `address_exact` signal. State this in
the module header, because the scorer's `distance` weight reads
`locationMatchType !== 'census_non_exact'`.

🔴 **Use `matchedAddress` for display, never the input** — the same rule `census.ts` documents.
