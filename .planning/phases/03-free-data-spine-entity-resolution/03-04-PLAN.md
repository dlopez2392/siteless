<objective>
Restructure the navigation from three destinations to six, ship the phone More sheet, and land
**every** string in 03-UI-SPEC § Copy Table into `src/lib/ui/copy.ts` in one edit.

Purpose: Phase 3 adds `/review`, `/sources` and `/businesses` to a shell that has Presets ·
Spend · Settings. Six bottom tabs is not a design — at 390px six tabs are 65px wide and the
label "Businesses" is ~72px, and the inherited contract makes the tab bar icon-**plus**-label
because the label is the accessible-name fallback. 03-UI-SPEC § 0 settles it: one partition
used twice — **Leads** (Presets · Review · Businesses) are the three phone tabs and the first
desk group; **Operations** (Sources · Spend · Settings) live behind a fourth `More` tab and in
the second desk group.

This plan owns `src/lib/ui/copy.ts` for the whole phase. The four screen plans read it and
never edit it, which is what lets them run in parallel.

🔴 **UI-SPEC Executor Rule 21 is a scheduled regression, not a surprise.**
`tests/e2e/touch-targets.spec.ts` asserts exactly **one visible** element per nav testid at any
viewport. With `nav-spend` and `nav-settings` inside a closed `Sheet` on phone that count
becomes **0**. The spec must be updated in the **same task** as the nav change. The fix pattern
already exists in that file — it opens the user menu before measuring `theme-switch`.

Output: two modified shell components, one new `more-sheet.tsx`, the full copy table, the
updated e2e spec.
