<objective>
Ship the shared ingest write path both desk scripts use, and prove DATA-04's four properties
plus the external key and criterion 5 against the live local database.

Purpose: D-05 makes a re-run idempotent by external id with a `payload_hash` diff — unchanged
rows only advance `last_seen_at`, changed rows update the payload *and* the derived columns, new
rows insert, and a row that vanished from the source is **marked, never deleted** (Overture
drops and re-adds ids between releases, so `gone` is a *report line*, not a state transition).

🔴 **The trap CONVENTIONS did not anticipate.** CONVENTIONS § Audit excludes `source_records`
from `log_event` precisely because this phase writes ~10k rows per run — but `businesses`
**is** in `EVENT_LOGGED`, and this phase writes ~92k `businesses` rows too. The first ingest's
~92k events are a one-time, correct, auditable cost (≈37 MB estimated). A second ingest with
nothing changed upstream must produce **zero**. That only holds if the `payload_hash` diff
gates the `businesses` write as well as the `source_records` write — which is the right design
anyway, and which turns into DATA-04's proof and mutation M20's target.

Output: three ingest modules, the DB fixture helpers, and three DB test files.
</objective>

🔴 **THE DEFECT THIS FILE EXISTS TO CLOSE.** `app.current_org_id()`
(`drizzle/0002_tenancy_functions.sql` line 5) is

```sql
select id from public.orgs
 where clerk_org_id = coalesce(app.jwt()->'o'->>'id', app.jwt()->>'org_id')
```

— it resolves the org from the `request.jwt.claims` GUC **and from nothing else**. `app.emit_event`
(`drizzle/0011`) opens with `v_org := app.current_org_id(); if v_org is null then raise exception
'emit_event: no current org' using errcode = '42501';`. In this repo `request.jwt.claims` is set in
exactly three places — `src/db/with-org.ts:60` (the app tier, real Clerk claims),
`scripts/check-test-db.ts:82` (a diagnostic) and `tests/db/_fixtures.ts:66` (`actAs`). **No desk
script sets it, and by D-01 none should have to**: the ETL connects as the migration owner, not as
a Clerk session. The asymmetry is what makes this easy to miss — the **actor** already has an ETL
path (`current_setting('app.actor_id', true)`), the **org** does not. A desk script that sets only
`app.actor_id` therefore raises `42501` on the **first `app.emit_event` of the first run**, and the
same hole takes down `app.record_merge` for every auto-merge in 03-14. Primary path, not an edge
case.

`resolveEtlOrg` does exactly three things, in this order:

1. Throws `EtlOrgRequiredError` when `clerkOrgId` is missing or empty. 🔴 **Never "the only org"** —
   that is a bug that appears once, and only once a second org exists (T-3-01).
2. `select id from orgs where clerk_org_id = $1` — throws `EtlOrgNotFoundError`, naming the argument
   it was handed, when no row comes back.
3. Installs the org claim for the rest of the transaction:

```sql
select set_config(
  'request.jwt.claims',
  json_build_object('o', json_build_object('id', $1::text))::text,
  true
);
```

Three deliberate omissions, each a silent defect if you "helpfully" add it:

- 🔴 **`sub` is omitted.** `app.emit_event` and `app.log_event` both resolve
  `coalesce(app.jwt()->>'sub', current_setting('app.actor_id', true), 'system')`. With no `sub` the
  actor falls through to the GUC and the run stays attributed `etl:<script>` (T-3-02). Adding a
  `sub` here would silently re-attribute ~92k first-run `events` rows to a fabricated user and
  nothing would fail.
- 🔴 **`o.rol` is omitted.** `app.current_org_role()` (0016) therefore returns NULL on an ETL
  connection, so a desk script cannot pass any role-gated definer (`app.set_budget_cap`). The ETL
  gets **org context, not admin**.
- 🔴 **No `set role`.** The desk script stays the owner (D-01). Switching to `authenticated` would
  put RLS in front of ~92k writes and re-introduce the grant layer these scripts deliberately sit
  behind.

🔴 **Both GUCs are transaction-LOCAL and die at COMMIT.** `setEtlActor` **and** `resolveEtlOrg` are
called inside **every** transaction — each ~500-row ingest batch and each transaction of the resolve
pass. Calling either once at startup sets it for the first transaction only and leaves every later
batch orgless.

The alternative — a caller-supplied `p_org_id` parameter on the definers — is **rejected**: an
app-tier session could then forge it, and T-3-08's entire argument for why `merged_by` and
`decided_by` are unforgeable is that the definers take **neither** `org_id` **nor** `actor_id` as a
parameter. Record that rejection in the file header so a later reader does not "simplify" it back.

**`src/lib/ingest/upsert.ts`**:

```ts
export function canonicalPayloadHash(selected: Record<string, unknown>): string
```
`sha256` over a **canonically key-sorted** JSON serialization of the *selected* fields, never
`JSON.stringify(row)`. Socrata's key order is stable today but is not a contract, and a
re-ordering would report every row as `changed`.

```ts
export async function upsertSourceRecord(tx, input): Promise<{ inserted: boolean; changed: boolean; id: string }>
```

```sql
insert into source_records (org_id, source_key, external_id, payload, payload_hash,
                            retention_class, source_version, fetched_at, last_seen_at)
values (...)
on conflict (org_id, source_key, external_id) do update
  set last_seen_at   = excluded.last_seen_at,
      source_version = excluded.source_version,
      payload        = case when source_records.payload_hash is distinct from excluded.payload_hash
                            then excluded.payload else source_records.payload end,
      payload_hash   = excluded.payload_hash
returning id,
          (xmax = 0) as inserted,
          (source_records.payload_hash is distinct from excluded.payload_hash) as changed;
```

- `external_id`: Overture → the GERS `id` **verbatim** as `text`, never cast to `uuid` (measured
  a bare UUID string, `e2d3a704-983c-4349-967d-9f6403722ccc`; the format is Overture's to
  change). Comptroller → `taxpayer_number || '-' || outlet_number` → `'32006170057-5'`.
- `returning (xmax = 0)` is the standard "was this an insert?" discriminator and is correct on
  PostgreSQL 17 and 18.
