**Exactly 4 sizes. Exactly 2 weights. Phase 3 adds neither.**

| Role | Size | Weight | Line height |
|------|------|--------|-------------|
| Body | 16px | 400 | **1.5 (24px)** |
| Label | 14px | 400 | 1.43 (20px) |
| Heading | 20px | 600 | 1.3 (26px) |

Weights: **400 Regular** and **600 SemiBold**. No 300, no 500, no 700.

Phase 3 role assignments (every one reuses an existing size — nothing new is invented for chips, source tags or counts):

- **Display 28/600 — not used on any Phase 3 screen.** Phase 2 reserved it for the money figures. The review queue's remaining count is deliberately *not* Display: the focal point of that screen is the candidate pair, and a 28px counter would compete with it. Stated here so nobody adds a fifth size trying to make the counter feel important.
- **Heading 20/600** — page titles ("Review queue", "Sources", "Businesses"), the two candidate `display_name`s in a review pair, the business `display_name` on the detail header, card titles, empty-state headings.
- **Body 16/400** — prose, the search input on `/businesses`, field values on the detail view, button labels on phone, empty-state and error body.
- **Body 16/600** — the review queue's remaining count, the external lead key, a number inside body flow.
- **Label 14/400** — **the inline source tag** (see § Color), metadata, table cells, timestamps, the pair score, the confidence-band figures, bottom-tab labels, the More-sheet row labels.
- **Label 14/600** — table column headers, **signal chip text**, badge text, sidebar group eyebrows ("Leads", "Operations").

**Numerals.** Every number compared or scanned gets `tabular-nums`: the four ledger counts on `/sources`, the confidence bands, the pair score, the name-similarity figure inside a chip, distances, the remaining count, lat/lng, the business count, dates in tables. The four count columns on `/sources` are right-aligned on desk and render as label/value rows on phone.

### Accent reserved for — exhaustive list (items 1–7 inherited, 8–9 added by Phase 3)

Accent (`#0F766E` / `#2DD4BF`) appears **only** on:

1. The **one** primary CTA on a screen (filled button). One per screen.
2. The **active** item in the desk sidebar, in the phone bottom tab bar, and — new surface, same rule — in the phone **More** sheet: accent label + accent icon + a 2px accent indicator.
3. The **focus ring** on every focusable element (2px, 2px offset, `:focus-visible`).
4. The **dollar figure** in the live estimate line and the month-to-date spend figure on `/spend`.
5. The **budget gauge fill** while spend is under 80% of the cap.
6. **Inline text links** inside body copy — which in this phase includes the `tel:` link on a business phone number and the "Open sources" / "Open businesses" links inside empty and error copy.
7. The **`Current` version badge** on the preset detail page.
8. **NEW — the "Same business" button** in the review queue's action bar. It is that screen's single primary CTA; "Different" and "Skip" are not accent.
9. **NEW — the external lead key** (`SL-7F3K2`) on the business detail header, as accent *text* at Body 16/600 tabular. Justification, and it is the same one item 4 rests on: this is the number that *is* the product on that screen — the string danlo reads aloud on a call and types into a CSV filter (D-19). It is not an action and does not violate "one accent action per screen".

Accent does **not** appear on: signal chips, inline source tags, the chain flag, the `Closed` badge, status badges on `/businesses`, the `/sources` ledger, the "Different" or "Skip" actions, the Unmerge action, table headers, card borders, or inactive nav items. **"All interactive elements" is never the answer.**

### New Phase 3 elements — explicit role assignment (none of these takes accent)

| Element | Role | Treatment |
|---------|------|-----------|
| **Agreement signal chip** ("phone exact", "same ZIP", "140 m apart", "name 0.81") | Muted | `Badge variant="secondary"` — `--secondary` fill, `--secondary-foreground` text, Label 14/600, pill radius. |
| **Disagreement / absence chip** ("different cluster", "no phone on either side", "3.1 km apart") | Muted foreground + border | `Badge variant="outline"` — 1px `--border`, `--muted-foreground` text. **The words carry the meaning** ("different", "no"), so the outline is redundancy, not the signal (colour is never the only signal). |
| **Inline source tag** ("Comptroller", "Overture", "Census geocoder") | Muted foreground | **Plain text, not a badge.** Label 14/400 in `--muted-foreground`, no border, no fill, no icon, always in the same position on every row. See the rationale below. |
| **Chain flag** ("Chain · 7 in Texas") | Muted foreground + border | `Badge variant="outline"`. A chain is a fact, not a fault (D-11: flag, never a merge). |
| **Status badge** on `/businesses` and the detail header — `Active` / `Merged away` | Muted | `Badge variant="secondary"`. |
| **`Closed` badge** (`closed_at` is set) | **Destructive surface** | `--destructive-surface` background, `--destructive-surface-foreground` text, plus the word "Closed" and the date. **Justification for extending destructive's reserved-for list:** a closed business is a hard stop of exactly the kind destructive already marks in this product (a refused run) — Phase 6 and Phase 7 must never surface it as a lead, and someone calling a dead business is the single most embarrassing failure this product can produce. It is a badge, never a button. |
| **Unmerge action + its confirmation** | Destructive | Destructive **outline** button on the merge row; the confirmation dialog's confirm button is destructive filled. |
| **Ingest run status** on `/sources` | Reuses Phase 2's tone map | `complete` neutral solid · `partial` warning · `failed` destructive — from `src/lib/ui/run-tone.ts`, the existing **server-safe** module (Executor Rule 5). No second tone map. |

**Why source tags are text and not badges.** D-18 puts a source tag on *every* field of the detail view — roughly ten of them on one screen. Ten bordered pills is ten boxes competing with the values they annotate, and the values are what danlo is reading. Plain muted text in a fixed column reads as a *column* rather than as ten objects (alignment does the grouping work that a border would otherwise do), costs no extra border colour, and cannot be mistaken for something tappable — which matters, because D-18 says always visible, **no tap**. The resulting house rule, which the executor must hold: **badges describe the state of a record; source tags are metadata text. A source tag is never a badge and never an accent.**

| Primary CTA — `/businesses/[id]` | **None accent.** The only action on the screen is **"Unmerge {name}"**, which is destructive and therefore never the accent CTA. |
| Empty — `/review`, work done | **"Queue clear"** |
| Empty — `/review`, nothing ingested yet | **"Nothing to review yet"** |
| Empty — `/sources` | **"No ingest has run yet"** |

| Error — unmerge failed | "The unmerge didn't complete. The two records are still merged exactly as they were — nothing was half-undone." → **"Try again"** · **"Open sources"** |
| **Destructive action — Unmerge (D-20)** | **Confirmation required.** A `Dialog` on desk / `Drawer` on phone, destructive tone, titled with both names, naming every consequence (key restoration, field restoration, the permanent `distinct` marking, the recorded actor and time). Confirm: **"Unmerge these two records"**. Dismiss: **"Keep them merged"**. Full copy in § Copy Table. |
| **Not destructive — "Same business" and "Different"** | **No confirmation on either, deliberately.** "Same business" creates a merge row and deletes nothing (ARCHITECTURE anti-pattern 9); its reversal is Unmerge on the detail view (D-20). "Different" writes a `distinct` decision; both records survive untouched and independent. A confirmation step on a queue worked from a phone would double every tap and is the fastest way to make danlo stop working it. This is also what keeps the inherited rule "nothing destructive and nothing irreversible sits in the thumb zone" true on this screen. |

Voice rules — inherited from `02-UI-SPEC.md` § Copywriting Contract and binding on every string below:

- **Name the number.** "142 pairs left to review" beats "Items pending".
- **Say what happened to the data.** Any failure states explicitly that nothing was recorded or nothing was half-undone, when that is true.
- **Every error ends with a way out** — a button, a link, or a concrete instruction naming the script to run at the desk.
- **No generic labels.** Never "Save", "Submit", "OK", "Cancel", "Delete", "Continue" on their own. A dismiss reads "Keep them merged", never "Cancel".
- **Times and dates are `America/Chicago`** and render through `formatLocal` (`src/lib/time.ts`), never a raw `Intl` call.
- **`display_name` renders verbatim.** An `ñ` on the screen is the business's own name (D-12). The normalized match key is never displayed anywhere.

## Screen Inventory & Layout Patterns

### 0. Navigation — the six-destination problem, decided

**The problem, stated plainly.** The shipped phone tab bar (`src/components/app-shell/mobile-tab-bar.tsx`) has **3** tabs: Presets `/presets` · Spend `/spend` · Settings `/settings/budget`. Phase 3 adds **3** destinations: `/review`, `/sources`, `/businesses`. Six bottom tabs is not a design: at a 390px design width, six tabs are 65px wide, and a 14px label reading "Businesses" is ~72px. The labels would truncate or disappear — and the inherited contract says the bottom tab bar is **icon-plus-label, never icon-only**, because the label is the accessible-name fallback. Four tabs is the largest set that keeps every label real text (97.5px per tab at 390px).

**The decision: one partition, used twice.** The six destinations split into two groups of three, and the *same* partition drives both breakpoints.

| Group | Destinations | Desk sidebar | Phone |
|-------|-------------|--------------|-------|
| **Leads** — the daily work | Presets · Review · Businesses | Group 1, under a "Leads" eyebrow (Label 14/600 muted) | **The three bottom tabs** |
| **Operations** — the desk work | Sources · Spend · Settings | Group 2, after a `Separator`, under an "Operations" eyebrow | **Inside the More sheet** |

**Desk sidebar (≥1024px), final order and icons** — 256px, `--sidebar` surface, rows unchanged at 44px / 8px radius / 16px horizontal padding / 20px icon / 8px gap / Body 16/400, exactly one row carrying accent:

| # | Label | Route | Active base | lucide icon | `data-testid` |
|---|-------|-------|-------------|-------------|---------------|
| — | *Leads* (eyebrow, not a link) | — | — | — | `nav-group-leads` |
| 1 | Presets | `/presets` | `/presets` | `list-checks` | `nav-presets` *(unchanged)* |
| 2 | Review | `/review` | `/review` | `git-compare` | `nav-review` |
| 3 | Businesses | `/businesses` | `/businesses` | `store` | `nav-businesses` |
| — | `Separator` + *Operations* eyebrow | — | — | — | `nav-group-operations` |
| 4 | Sources | `/sources` | `/sources` | `database` | `nav-sources` |
| 5 | Spend | `/spend` | `/spend` | `circle-dollar-sign` | `nav-spend` *(unchanged)* |
| 6 | Settings | `/settings/budget` | `/settings` | `settings` | `nav-settings` *(unchanged)* |

`building-2` stays reserved for the org header and is **not** reused for Businesses — two meanings on one glyph in one sidebar is a defect.

**Phone (<640px), final tab set:** **Presets · Review · Businesses · More** — four equal tabs, 64px + `env(safe-area-inset-bottom)`, 24px icon over a Label 14/400 text label, active tab = accent icon + accent label + a 2px accent bar on the top edge. **Why Spend loses its tab and Presets keeps one** *(default — danlo may override in CONTEXT.md)*: the urgent Spend state is already **pushed** to the user — `BudgetBanner` renders above the content on every single route at ≥80% and carries "See spend by provider" (D-12). A tab for a screen whose only time-critical state arrives unbidden is a tab spent on nothing. Presets, by contrast, has a phone-designed create flow with its own thumb-zone action bar (`02-UI-SPEC` § 1). The desk sidebar gains Triage at the top of the Leads group.

### 1. Review queue — `/review` (D-13, D-15, D-16)

**Purpose.** Work the 80–95 confidence band to zero, from a phone, one pair at a time.

**Focal point:** **the candidate pair** — concretely, the two `display_name`s at Heading 20/600, one per side. They are the only thing a human can actually adjudicate, and everything else on the screen exists to support that judgement.

**What draws the eye first, in order:** (1) the left card's `display_name`, (2) the right card's `display_name`, (3) the signal chip band that sits physically between them, (4) the action bar. The remaining count and the score are deliberately quiet — Label/Body at the top of the screen, never larger than a name.

**Hierarchy:** page title "Review queue" (Heading 20/600) → remaining count + ordering note (Body 16/600 tabular + Label 14/400 muted) → the pair → chip band → actions.

**Desk (≥1024px):** two equal `Card` columns, 24px gap, 24px inner padding. Beneath both columns, a full-width **chip band** (the chips cannot sit *between* two side-by-side columns, so they sit directly under them, visually bridging the pair). Beneath that, a single action row: **"Same business"** (accent filled) · **"Different"** (outline) · **"Skip"** (ghost), left-aligned, 44px tall.

**Phone (<640px):** card A → **chip band** → card B → sticky action bar in the thumb zone (D-13's exact stacking). The sticky bar is `--card` surface, 1px top border, 16px padding, `env(safe-area-inset-bottom)` below it and above the tab bar, and it is **two rows**:
- row 1: **"Same business"**, full width, 48px tall, accent filled;
- row 2: **"Different"** and **"Skip"**, 48px tall, 8px gap, equal width, outline and ghost.

Three 16px labels side by side do not fit a 390px row without dropping to 14px button text, which the type contract forbids. The two-row bar keeps the primary action full-width in the thumb zone and both secondaries reachable. The content area's bottom padding accounts for the bar's full height plus the tab bar.

**Each side of the pair shows, in this order** (D-13): `display_name` (Heading 20/600, verbatim) · address (Body 16/400) · phone (Body 16/400 tabular, formatted for display) · category / cluster (Label 14/400 muted) · **source** (inline source tag, Label 14/400 muted) · **`Closed {date}`** badge if `closed_at` is set · **`Chain · {n} in Texas`** badge if `chain_key` is set. A field the source does not carry renders the literal string **"Not on this record"** in `--muted-foreground` — never a blank cell, never an em-dash alone.

**The chip band** renders the component vector, never a bare score (§ Specific Ideas, danlo's own words): `phone exact · name 0.81 · 140 m apart · same ZIP · different cluster`. Chips are **static text, not controls** — no hover, no tap, no 44px obligation — grouped in a container labelled "Why these two scored 87" so a screen reader reaches them as a set. Agreement chips are `secondary`; disagreement and absence chips are `outline`. The pair score renders once, right-aligned in the header row, as **"Score 87 of 100"** in Label 14/400 muted tabular: present because the queue is score-ordered and danlo needs to know where in the band he is, never the largest thing on screen, and never shown without its chips.

**Ordering and end state (D-16):** highest score first; the header carries the remaining count; the queue reaches an **explicit "Queue clear"** state. **This is the shape TRI-03 reuses in Phase 7 — do not invent a second one there.**

**Not in this phase, stated so nobody builds it:** no undo toast on a decision (TRI-02, Phase 7 — unmerge is the Phase 3 reversal path, D-16/D-20); no swipe gesture (MOB-02, Phase 7 — `motion` drag does not appear on this screen); no bulk actions and no keyboard shortcuts (TRI-06/TRI-07, v2); no per-field winner picking (D-14 — survivorship is fixed, the UI decides same/different only).

**Components:** `card`, `badge`, `button`, `separator`, `empty`, `skeleton`, `alert`, `item`. All installed.

### 2. Sources ledger — `/sources` (D-06, D-17)

**Purpose.** "It reads like a ledger" (§ Specific Ideas): source · version ingested · last run · added / changed / unchanged / gone. This is the success-criterion-1 artifact made visible.

**Focal point:** **the four count columns**, as a block. The eye lands on the leftmost source name and travels right across `added / changed / unchanged / gone` — the only `tabular-nums` on the screen, right-aligned on desk so the digits line up into a column that can be read down as well as across. That alignment *is* the design; nothing on this screen is accent.

**Hierarchy:** page title "Sources" (Heading 20/600) → one-line explanation (Label 14/400 muted) → the ledger → the attribution block.

**Rows — exactly four, always present even before their first run** (D-17): **Comptroller permits** (`jrea-zgmq`) · **Comptroller closures** (`3kx8-uryv`) · **Overture places** · **Census geocoder**.

**Desk:** `Table`. Columns: `Source` · `Version ingested` · `Last run` · `Added` · `Changed` · `Unchanged` · `Gone`. The four counts are right-aligned and tabular. The source cell carries the dataset id on a second line in Label 14/400 muted, plus the run status `Badge` (`Complete` / `Stopped early` / `Failed`) using Phase 2's existing tone map from `src/lib/ui/run-tone.ts`.

## Accessibility & Touch

Inherited wholesale from `02-UI-SPEC.md` § Accessibility & Touch. What Phase 3 adds:

- **Touch targets ≥44×44 CSS px** on every interactive element on phone. The three review actions are **48px tall** — above the floor, because they are the only controls on the screen and they are pressed hundreds of times in a sitting.
- **Thumb zone (MOB-01):** the review queue's action bar is the sticky bar directly above the tab bar. It holds nothing destructive and nothing irreversible — "Same business" is reversible by Unmerge and "Different" deletes nothing (§ Copywriting Contract).
- **Signal chips are static text.** They are not controls, carry no tab stop and no 44px obligation, and live inside a container with an accessible group label ("Why these two scored 87") so a screen reader reaches the whole vector as a set rather than as loose fragments.
- **Source tags are text, always visible, never a tooltip and never behind a tap** (D-18). A tooltip-only provenance would be invisible on a phone, which is the device this product is for.
- **Advancing the queue moves focus.** After a recorded decision, focus moves to the new pair's first heading (`tabindex={-1}`), and the remaining count region is `aria-live="polite"` so the new count is announced. Without this a keyboard or screen-reader user is left on a button whose surrounding content silently changed.
- **The remaining count and the "Queue clear" state share one live region** — reaching the end state must be announced, not merely rendered.
- **No icon-only actions anywhere in this phase.** "Copy lead key" and "Unmerge {name}" are text buttons. The only glyph-led control is the phone **More** tab, which carries a visible text label like every other tab.
- **Colour is never the only signal:** `Closed` carries the word and the date; chain carries the word and the count; agreement vs disagreement chips are distinguished by their wording ("different", "no") before they are distinguished by their fill.
- **Contrast** is measured in both themes for every new pair before it ships (§ Theme).
- **Numbers and dates** render through `formatLocal` / the pinned money and phone formatters — zone *and* locale, never a raw `Intl` call in a component (CONVENTIONS § Time; recorded BIS SSR hydration mismatch for `es-*`).
- **`data-testid` on every interactive element**, convention `{screen}-{element}-{qualifier}`, kebab-case, stable across copy changes: `nav-review`, `nav-businesses`, `nav-sources`, `nav-more`, `more-sheet`, `review-remaining`, `review-pair`, `review-side-a`, `review-side-b`, `review-chips`, `review-score`, `review-action-same`, `review-action-different`, `review-action-skip`, `review-queue-clear`, `review-empty`, `sources-table`, `sources-row-{sourceKey}`, `sources-count-{sourceKey}-{added|changed|unchanged|gone}`, `sources-confidence-toggle`, `sources-attribution`, `businesses-search`, `businesses-filter-cluster`, `businesses-filter-status`, `businesses-count`, `businesses-row-{id}`, `businesses-show-more`, `business-detail`, `business-lead-key`, `business-lead-key-copy`, `business-field-{field}`, `business-field-{field}-source`, `business-source-record-{id}`, `business-merge-row-{mergeId}`, `business-unmerge-{mergeId}`, `business-unmerge-confirm`, `business-unmerge-dismiss`.

## Motion

`motion@13.4.0` is already in the stack. On this phase's screens it does exactly two jobs.

| Animation | Spec |
|-----------|------|
| Queue advance | 150ms: the decided pair exits at opacity 1 → 0 with an 8px upward translate; the next pair enters at opacity 0 → 1. The new pair is mounted before the old one is removed — the region is never empty. |
| Collapsible confidence distribution | Radix's own height transition, 200ms. Do not wrap it in `motion`. |

Everything else — dialogs, drawers, sheets, the More sheet — uses Radix's and vaul's own springs. **Two animation systems on one element is how a drawer ends up fighting itself.**

**No swipe, no drag, no card stack in this phase.** MOB-02's gesture layer is Phase 7's; `motion`'s `drag` prop does not appear in `/review`.

**`prefers-reduced-motion`** (recorded 956 Woodworks defect: a naive reduced-motion rule blanked the hero): use `useReducedMotion()` plus the media query, and **disable the animation, never the content.** Durations go to 0, transforms are dropped, the next pair appears immediately at its final state. There is no code path in which a reduced-motion user sees an empty queue region.

## Executor Rules

Rules 1–16 of `02-UI-SPEC.md` § Executor Rules remain in force **unchanged**. The ones most likely to be violated by this phase's work are restated first; 17–27 are new.

1. **Tailwind v4 arbitrary values use `[var(--x)]`, never `[--x]`.** v4 dropped the shorthand and emits invalid CSS silently.
2. **Painted values, never CSS custom properties, for anything a test pins.** Probes assert the computed value (`rgb(15, 118, 110)`), never a variable name, never `.includes(...)`.
5. **A `"use client"` module's exports are client references inside a server component** — plain data included, resolving to `undefined` at runtime with typecheck, lint and build all green. Copy constants, tone maps and label maps stay in server-safe modules (`src/lib/ui/copy.ts`, `src/lib/ui/run-tone.ts` — no `"use client"`). Every string in § Copy Table lands in `src/lib/ui/copy.ts`, not inline in a component.
6. **No hand-rolled surfaces.** Every card, sheet, drawer, badge, input and table on these four screens is the shared shadcn primitive. Grep for `bg-card`, `rounded-`, `border border-` on raw `div`s before calling a screen done — a treatment applied only to the shared `Card` while hand-rolled divs sit beside it reaches almost nothing, and every review passes because the tests pin the `Card`.
8. **Review screenshots are of the real screens, in both themes, on the built app**, never a styleguide page and never dev mode. Assert `innerHeight > 0` and visibility before measuring anything.
13. **`tailwind.config` stays empty.** No `tailwind.config.ts` is created.
15. **Never add a `geist` package.** The font is Inter.

**New in Phase 3:**

17. **`display_name` renders verbatim. The normalized match key is never displayed** (D-12). `name_norm` does not appear in any component, any table cell, any tooltip or any `data-` attribute, and it must be registered in `src/lib/export/registry.ts` so `tests/unit/no-internal-leak.test.ts` scans it. `internal_notes` never renders on any screen in this phase.
18. **The external lead key is display-only.** `SL-7F3K2` is never a foreign key, never a route parameter, never a query key. `/businesses/[id]` takes the internal uuid and calls the `src/lib/ids.ts` guard that `tests/unit/ids.test.ts` walks for every `[id]` route (D-19).
19. **Never run `npx shadcn init` again.** It rewrites `src/app/layout.tsx` and its font import. The only permitted CLI call in this phase is `npx shadcn@4.21.0 add <component> -y`, and no component this phase needs is missing — so in practice there is no CLI call at all.
20. **Never advance the queue before the decision is recorded.** The pressed button enters a busy state and the pair advances only on a successful write. Optimistic advance with a failure toast is Phase 7's undo pattern (TRI-02) and is explicitly not built here; a silently dropped decision is invisible, and the whole value of this queue is that every pair got a human answer.
21. **Moving `nav-spend` and `nav-settings` into the phone More sheet changes their visibility.** `tests/e2e/touch-targets.spec.ts` asserts exactly one visible element per nav testid at any viewport; inside a closed `Sheet` that count is 0. Update the spec **in the same task** as the nav change, and grep `tests/e2e/` for every nav testid and class the change touches — a retired or relocated hook fails silently (recorded BIS lesson).
22. **Source tags are text; badges are state.** A source tag is `Label 14/400` in `--muted-foreground` with no border, no fill and no icon, in a fixed position on every row. It is never a `Badge`, never accent, never a tooltip, never behind a tap (D-18).
23. **"Different" is not a destructive control and gets no destructive styling and no confirmation.** "Same business" gets no confirmation either. **Unmerge is the one destructive action in this phase and always opens its confirmation.**
24. **No chart library.** The confidence distribution is composed from `Progress` and painted divs. `recharts` does not enter the bundle.
25. **`tabular-nums` on every compared number:** the four ledger counts, the confidence bands, the pair score, the name-similarity figure, distances, the remaining count, lat/lng, business counts, table dates.
26. **Dates, money and phone numbers go through the pinned helpers** (`formatLocal` from `src/lib/time.ts`, `formatUsd`, a `libphonenumber-js` display formatter). No component in `src/components/` calls `Intl` directly — the zone and the locale are both pinned, or the same record renders a different day on Vercel than on a Chicago laptop.
27. **The four source rows on `/sources` render before any run exists.** They are static structure, not data. A screen that shows nothing until an ingest has run cannot tell you that an ingest has not run.
