the exact analog — an `import 'server-only'` module exporting a `tx`-taking `read*` function
**and** a `withOrg`-opening `list*` wrapper, so a page can compose several reads inside one
transaction.

second `withOrg` opened inside a first waits forever on a connection the outer one holds and the
**request hangs rather than failing**. `/businesses/[id]` reads the business, its source records,
its merge history and its aliases — all inside one `withOrg`.

Output: three query modules, two actions, the guard test extension, two DB tests.

**`review-queue.ts`** — `readReviewQueue(tx)` returns
`{ top: CandidatePairView | null; remaining: number }`.

```sql
select … from merge_candidates mc
  join businesses a on a.id = mc.left_id
  join businesses b on b.id = mc.right_id
 where mc.org_id = (select app.current_org_id())
   and mc.decision = 'pending'
   and mc.score >= 80
 order by mc.skipped_at nulls first, mc.score desc, mc.id
 limit 1
```

🔴 `skipped_at nulls first` is D-13's "Skip leaves this pair pending and moves on": a skipped
pair sinks below everything undecided and resurfaces once the rest is worked. `remaining` is the
count over the same predicate.

`CandidatePairView` carries, per side: `displayName` (verbatim), `street`, `city`, `postal`,
`phoneE164`, `basicCategory`, `clusterKey` **resolved to its `industry_clusters.display_name`**,
`sourceKey`, `closedAt`, `chainKey` and its statewide member count — plus the pair's `score` and
its `features` component vector. 🔴 `name_norm` is **not** selected. It renders nowhere, ever
(D-12, UI-SPEC Rule 17), and the chip band renders `features`, so `name_norm` must not be in it.
🔴 A key is never shown to a person — resolve `cluster_key` through the reference table, as
`preset-cards.ts`'s `geographyLabelOf` does.

**`sources.ts`** — `readSources(tx)` returns **exactly four** rows, one per
`('tx_comptroller','tx_comptroller_closures','overture','census_geocoder')`, **whether or not
that source has ever run** (UI-SPEC Executor Rule 27: the four rows are static structure, not
data; a screen that shows nothing until an ingest has run cannot tell you that an ingest has not
run). Left-join the latest `ingest_runs` row per `source_key` with a `left join lateral`
(`order by started_at desc limit 1`), returning `sourceVersion`, `lastRunAt`, `status`, `added`,
`changed`, `unchanged`, `gone`, `error` and `stats`. Also expose the Overture row's
`stats.confidence_bands` for the `Collapsible` distribution.

🔴 `lastRunAt` comes back from `tx.execute` as a **string with a space separator** — parse it
as-is through the shared `instantOf`/`requireInstant`; never ISO-ify it, and never call `Intl`
here.

**`businesses.ts`** — two reads:

`readBusinessList(tx, { query, clusterKey, status, limit, offset })` — the searchable list.
Columns: `id`, `displayName`, `city`, `clusterKey` → display name (or the literal "no cluster
mapped" state), the set of `sourceKey`s present (from `source_records`), `status`, `closedAt`.
50 rows per page plus a total count. 🔴 **This is the ONE place `unaccent(` is permitted under
`src/`** — the free-text predicate:

```sql
where unaccent(b.display_name) ilike unaccent('%' || $q || '%')
   or unaccent(coalesce(b.legal_name,'')) ilike unaccent('%' || $q || '%')
   or b.external_key = upper($q)
```

Add this exact file path to the allow-list in `tests/unit/sql-never-normalizes.test.ts` **in the
same commit**, so the gate keeps its two-entry allow-list and M24 still reds it when `unaccent`
appears in the blocking SQL.

`readBusinessDetail(tx, id)` — everything `/businesses/[id]` renders, in **one** transaction:
the business row with each field's `*_source_id` resolved to its `source_key` (for the D-18
inline source tag), its `source_records` (source, version, external id, first seen, last seen),
its `business_merges` newest first (winner, loser, reason, score, actor, merged_at, undone_by,
undone_at) and its `business_aliases`. 🔴 A field whose `*_source_id` is NULL must be
distinguishable from a field whose value is NULL — the UI renders "Not stored" with the tag
"No durable source", which is the honest rendering of CONVENTIONS § Retention.
🔴 `internal_notes` and `name_norm` are **never selected**.

An unknown id and a foreign id are the **same** answer: return `null` and let the page call
`notFound()`. No ownership check in the module — RLS already settled it, and saying which it was
would confirm to a wrong-tenant caller that the row exists.

**`src/server/actions/record-review-decision.ts`**

```ts
'use server';
export async function recordReviewDecision(input: unknown): Promise<ActionResult<{ remaining: number }>>
```

- 🔴 `const { userId, orgId } = await requireOrg();` is the **first statement** (T-3-10). Build
  claims with `orgClaims()`.
- `z.strictObject({ candidateId: z.uuid(), decision: z.enum(['merged','distinct','skip']) })`,
  `safeParse`, `fail('validation', …)` on failure.
- One `withOrg` transaction:
  - re-read the candidate **under RLS** before deciding; a foreign or unknown id →
    `fail('not_found', NOT_FOUND('pair'))`
  - a candidate already decided → `fail('conflict', …)` (somebody decided this pair first)
  - `'merged'` → `mergePair(tx, { candidateId, …, reason: 'review' })`, which calls the
    `app.record_merge` definer
  - `'distinct'` and `'skip'` → `recordCandidateDecision(tx, …)`, which calls
    `app.record_candidate_decision`
  - return the new `remaining` count so the queue header updates without a second round trip
- `revalidatePath('/review')` and `revalidatePath('/businesses')` on success.
- 🔴 An expected refusal is a **result, not a throw**. Only a genuine bug throws; a thrown action
  is a 500 the UI has no copy for. Every message comes from `src/lib/ui/copy.ts`.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-10 | Elevation of privilege | `recordReviewDecision`, `unmergeBusiness` | mitigate | `requireOrg()` is the first statement (enforced by the static guard test); the candidate and the merge row are re-read **under RLS** before anything is written; `proxy.ts` carries no authorization by design (CVE-2025-29927) |
| T-3-08 | Repudiation | decision and merge attribution | mitigate | Both actions write only through `SECURITY DEFINER` functions that read the actor themselves; `authenticated` holds no write DML on either table |
| T-3-09 | Information disclosure | foreign ids | mitigate | A foreign id and an unknown id are the same `not_found`/`null`, so the response does not confirm a row's existence to a wrong-tenant caller; two orgs in every fixture |
| T-3-11 | Information disclosure | query projections | mitigate | `name_norm`, `street_norm`, `phone_blockable` and `internal_notes` are never selected; `provenance never leaks the internal columns` asserts on the key set |
| T-3-05 | Tampering | the `/businesses` search predicate | mitigate | `unaccent(... ilike ...)` over a **bound** parameter; the query string never becomes SQL text, and the allow-list entry is a named file path rather than a blanket exemption |
| T-3-13 | Information disclosure | `external_key` search | accept | Searching by lead key is org-scoped by RLS; the key is not a route parameter and the namespace is 1.07e9 at 0.009 % occupancy |
