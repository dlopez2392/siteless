**Connection.** Owner connection, same as `seed.ts`. 🔴 **Per transaction, both of these, in this

🔴 **Neither is optional and neither survives a COMMIT.** `app.current_org_id()`
(`drizzle/0002_tenancy_functions.sql` line 5) resolves the org from `request.jwt.claims` and from
nothing else; `app.emit_event` raises `42501 'emit_event: no current org'` when it comes back null.
An owner connection sets no claims, so `resolveEtlOrg` is what installs them — see 03-09 for the
full reasoning and the deliberate omission of `sub`. A run that calls these once at startup rather
than per transaction works for exactly one batch and then dies at `finishRun()`, ~35,000 rows in.
Both GUCs are `set_config(..., true)`: transaction-LOCAL, dying at COMMIT, which is what keeps the
next batch from inheriting the previous org.

**Fetch.** One `socrataQuery('jrea-zgmq', …)` with
`$where = outlet_county_code in ('031','108','214','245')` built through `quote()` and
`paddedCountyCode()`, `$order=taxpayer_number,outlet_number` (🔴 mandatory — without it Socrata
gives no stability guarantee across pages), `$limit=50000` and the `$offset` loop. Read the
source version from `socrataRowsUpdatedAt('jrea-zgmq')` and record it on `ingest_runs` **and**
on every `source_records` row.

**Transform.** `permitRowSchema.parse` per row, then `comptrollerRowToSourceRecord`, then the
normalizers: `nameNorm(outlet_name)`, `addressKey(outlet_address, outlet_zip_code)`.
🔴 `outlet_address` is the location — **never `taxpayer_address`**, which is a mailing address.
Fold `outlet_city` through `cities.name_variants` (the Phase 2 ∥ 3 shared contract) before
storing `city`. Resolve `cluster_key` from the seeded half-open NAICS ranges; an unmapped NAICS
leaves `cluster_key` NULL and is counted in `stats.unmapped_naics` — the row stays in the spine
and never enters the funnel (D-02).

**Write.** `startRun` → per row `upsertSourceRecord` then `upsertBusinessFromSource` (which
gates on the hash diff) → `countGone` → `finishRun` with
`{added, changed, unchanged, gone, totalSeen, stats}`. Batch the upserts in transactions of
~500 rows so a failure does not roll back 35,000 writes; each transaction re-sets the ETL actor
GUC, because it is transaction-LOCAL.

**Report.** Print the four counts, the source version and the wall clock, and persist the same
numbers to `ingest_runs` — D-06 requires them persisted, not printed, so `/sources` can render
them.

🔴 Drizzle traps this file will hit: a JS array (the four county codes) interpolated into a
`sql` template becomes N placeholders — bind one array literal with a cast or use `sql.join`;
a `Date` bound through `tx.execute` throws — bind `toISOString()` with `::timestamptz`.

**The closure pass**, as its own `ingest_runs` row with
`source_key='tx_comptroller_closures'`, `dataset_id='3kx8-uryv'`:

- one request: `loc_county in ('31','108','214','245') and out_of_business_date IS NOT NULL`
  🔴 **UNPADDED** — `unpaddedCountyCode()`, never `paddedCountyCode()`. The padded form returns
  37,875 rows instead of 58,937 and `loc_county='031'` returns **zero**. Expect **21,509** rows.
- write each as a `tx_comptroller_closures` source record keyed
  `external_id = tp_number || '-' || loc_number` — the **same key shape** the permits feed uses,
  which is what makes the exact match work
- then, exact match only, no fuzzy logic (D-03):

```sql
update businesses b
   set closed_at           = sr.closed_at,
       closed_at_source_id = sr.id
  from source_records sr
 where b.org_id = $1 and sr.org_id = $1
   and sr.source_key = 'tx_comptroller_closures'
   and sr.external_id = b.comptroller_key
   and b.closed_at is distinct from sr.closed_at;
```

🔴 On a business that has been merged away the closure applies to the **winner**, resolved
through `coalesce(merged_into_id, id)`.
🔴 `out_of_business_date` arrives as `"1993-03-03T00:00:00.000"` with **no zone suffix**.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01 | Tampering | `--org` | mitigate | The org is resolved from an explicitly passed `clerk_org_id`; the script throws a named error rather than defaulting, and `ingest-comptroller refuses to start without an org` is the standing proof |
| T-3-04 | Tampering | the SoQL `$where` | mitigate | Built from seeded county codes and NAICS ranges only, through `quote()`; no caller input reaches SoQL in this phase |
| T-3-05 | Tampering (SSRF) | hosts | mitigate | Two constant hosts, both module-level constants in `src/lib/socrata/client.ts` and `src/lib/geocode/census-batch.ts`; the address is a CSV field in a POST body, never a URL |
| T-3-03 | Tampering | row ingestion | mitigate | `zod` on every Socrata row and every Census CSV line before it reaches the driver; every value a bound parameter |
| T-3-02 | Repudiation | ETL attribution | mitigate | `set_config('app.actor_id','etl:ingest-comptroller', true)` per transaction; `app.emit_event` resolves the Clerk `sub` first so a real session always wins, and `resolveEtlOrg`'s synthetic claim deliberately carries no `sub` so the ETL never impersonates a user |
| T-3-15 | Elevation of privilege | ETL org context | mitigate | `resolveEtlOrg(tx, clerkOrgId)` runs in every transaction and installs a transaction-LOCAL `request.jwt.claims` carrying `{o:{id}}` only — no `sub`, no `o.rol`, no `set role`. The ETL gets org context, not admin, and the claim dies at COMMIT |
| T-3-12 | Denial of service | the geocode pass | mitigate | `p-limit(3)`, 1,000-row chunks, three attempts with 2 s/8 s/30 s backoff; a dead chunk is recorded as `chunks_failed`, never retried forever |
| T-3-14 | Information disclosure | CI | mitigate | `scripts/**` is the only allow-listed network caller; `tests/unit/no-network.test.ts` enforces it and `tests/unit/no-google-credential.test.ts` stays green |
