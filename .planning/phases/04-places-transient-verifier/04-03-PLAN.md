**partition**:
- `PARTITION_COUNT = 4`
- `fnv1a32(s: string): number` — 32-bit FNV-1a over UTF-16 code units (offset 2166136261, prime 16777619, `Math.imul`, `>>> 0`). Pin: `fnv1a32('') === 2166136261`, `fnv1a32('a') === 3826002220`.
- `partitionOf(cellKey: string): number` = `fnv1a32(cellKey) % PARTITION_COUNT`. The caller builds `cellKey` (04-04 exports `cellKey()`); this module never imports expand-cells.
- `weeksSinceEpoch(instant: Date, timeZone: string = APP_TZ): number` — take `localDate(instant, timeZone)`, find that local date's Monday, and return whole weeks since Monday 1970-01-05 using date-only arithmetic on `Date.UTC(y, m-1, d)` values (never instant math across the zone).
- `currentPartition(instant: Date, timeZone: string = APP_TZ): number` = `weeksSinceEpoch(instant, timeZone) % PARTITION_COUNT`.
- `isoWeekOf(instant: Date, timeZone: string = APP_TZ): { isoWeek: number; mondayIso: string; sundayIso: string }` — display only; kept separate from the index (ISO week mod 4 repeats at week 53 → week 1).
Named tests (all under `describe('partition')`):
- `a cell keeps its partition when cells are added` (M47): partitions of 5 cell keys computed alone equal their partitions computed inside a list of 17 with the 5 shuffled.
- `partitions rotate weekly`: 4 consecutive Mondays (noon Chicago) → four distinct values, the 5th equals the 1st.
- `one instant in two zones gives opposite partitions`: `new Date('2026-09-28T03:30:00Z')` (Sunday 22:30 Chicago, Monday 03:30 UTC) → `currentPartition(i)` ≠ `currentPartition(i, 'UTC')`.
- `iso week is for display and crosses year ends`: `isoWeekOf(new Date('2027-01-01T18:00:00Z')).isoWeek === 53`.

**change-detect** (`diffTile(stored: ReadonlySet<string>, seen: readonly string[], opts: { hasBaseline: boolean }): { verdict: ChangeVerdict; added: string[]; gone: string[] }`), `ChangeVerdict = 'baseline' | 'unchanged' | 'new' | 'gone' | 'both' | 'saturated'`, `SATURATION_RESULTS` imported from nowhere — use the literal constant `IDS_ONLY_SATURATION = 60` exported here:
- `!hasBaseline` → `baseline`, `added` = all seen, `gone` = []
- equal sets → `unchanged`
- only additions → `new`; only removals → `gone` (a place missing from the listing is `gone`, never deleted — 04-15 sets `gone_at`); both → `both`
- `seen.length === 60` → `saturated` regardless of the diff, with `added`/`gone` still computed (a leaf now at 60 needs a paid re-sweep and subdivision)
- duplicates in `seen` are de-duplicated before diffing; output arrays are sorted
Named tests: `change detection: unchanged`, `change detection: new`, `change detection: gone`, `change detection: both`, `change detection: saturated`, `change detection: baseline`.
  </behavior>
