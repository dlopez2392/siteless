## Typography — inherited from `02-UI-SPEC.md` § Typography, confirmed

**Exactly 4 sizes. Exactly 2 weights. Phase 4 adds neither.**

| Role | Size | Weight | Line height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 (24px) |
| Label | 14px | 400 | 1.43 (20px) |
| Heading | 20px | 600 | 1.3 (26px) |
| Display | 28px | 600 | 1.2 (34px) |

Weights: **400 Regular** and **600 SemiBold**. No 300, 500 or 700.

Phase 4 role assignments. Every one reuses an existing size. Nothing new is invented for counters, SKU rows, ledger numerals or chips.

- **Display 28/600.** Used only for **the run's actual cost** on the run report header (`$2.31`). Painted foreground, **not accent** (§ Color). This extends Display's role list by one item, the same kind of number Phase 2 reserved Display for: money the product spent. The rationale is the parent spec's own ("the numbers that *are* the product"). No other Phase 4 element is Display. Tile counts, place counts and the remaining review count are not Display.
- **Heading 20/600.** Page titles ("Run report", "Review queue"), card titles ("Requests", "Tiles", "Outcomes", "Google Maps check", "Other ways to run", "Recent runs", "Google Places (transient)"), the spine business `display_name` in a Google review item, confirmation titles, and empty-state headings.
- **Body 16/400.** The status sentence body, stopped-reason and truncation alert text, the signal value on business detail ("No website listed"), button labels on phone, empty/error bodies, and the Places-mode notice.
- **Body 16/600.** The one-line status summary on the run header ("Complete — 68 tiles searched"), the review remaining count, and the counts in the run report's count grids (tabular).
- **Label 14/400.** Source tags, **including the "Google Maps" attribution**; the date beside it; table cells; the estimate range line under the cost; the "Updated 2:14:05 PM" line; the per-action cost line on preset detail; the tentative-reason line; and metadata.
- **Label 14/600.** Table column headers, badge text (run status, `Tentative`, `Set`), signal-chip text, and count labels in the run-report grids.

**Numerals.** Every compared number gets `tabular-nums`. This covers request counts per SKU, money, tile counts, place counts, per-cluster counts, host-class counts, place-id and coordinate counts, the oldest-coordinate age, the purge count, scores, similarity figures, distances, the ISO week number and every timestamp. Count columns are right-aligned on desk. On phone they render as label/value rows, the `/sources` pattern.

**Numbers never animate.** On a refresh a value is replaced in place, and `tabular-nums` keeps the column from jittering. There is no count-up tween in any motion mode (§ Motion).

**The one typographic exception is a legal mark, not a family.** Google's policy fixes the "Google Maps" text attribution as *"Roboto with sans-serif fallback · weight 400 · normal style · 12–16sp · normal spacing"*. The tag therefore declares `font-family: Roboto, sans-serif` at **Label 14/400**, which is inside Google's 12–16 range and uses an existing size and weight.
- **No font file is loaded and no package is added.** Devices with a system Roboto render it; everything else takes the sans-serif fallback Google explicitly permits.
- The design system still has one family (Inter). The size and weight counts are unchanged.
- This declaration lives in exactly one class (`.google-maps-attribution`, § Color) and is used by exactly one component (Executor Rule 29).

### The new token: `--google-attribution`

**Why a new token.** Google's policy allows the text attribution in exactly three colours: *"White, black (#1F1F1F), or gray (#5E5E5E) with 4.5:1 contrast minimum."* The inherited `--muted-foreground` (`#5B686D` / `#93A1A5`) is none of them. The inherited `--foreground` (`#101619` / `#E7EDEE`) is none of them either. PLACE-06 requires the attribution requirements to be met, so the colour is painted exactly as Google specifies.

**Declaration.** Declare `--google-attribution: #5E5E5E;` on `:root` and `--google-attribution: #FFFFFF;` on `.dark`. Both are literal values, never composed from another token, so the `:root` rule (Executor Rule 3) has nothing to bite on. Map it through `@theme inline` as `--color-google-attribution`.

**Measured contrast** (on the card surface, where every tag renders):

| Pair | Ratio | Passes |
|------|-------|--------|
| `#5E5E5E` on `#FFFFFF` (light) | **6.49:1** | Google's 4.5:1 and WCAG AA |
| `#FFFFFF` on `#161E21` (dark) | **16.9:1** | Google's 4.5:1 and WCAG AA |

**Scope.** This is not an accent and not a semantic colour. It paints two words, "Google Maps", and nothing else. It is never a fill, never a border and never an icon.

In practice the tag reads almost identically to its muted neighbours in light mode. In dark mode it reads one step brighter than the neighbouring tags. That visible difference is acceptable, and it serves Google's own *"visually distinguish Google Maps Platform Content"* rule.

Voice rules, inherited from `02-UI-SPEC.md` and `03-UI-SPEC.md` and binding on every string below:

- **Name the number.** "3 tiles still hit Google's 60-result limit" beats "Some results truncated".
- **Say what happened to the money and to the data.** Every stop, refusal and failure says whether anything was charged and whether anything was written or half-written.

- **Stopped reasons are machine keys in the database and sentences on screen.** `runs.stopped_reason` values (`budget_cap_reached`, `exceeded_estimate`, …) never render raw (Executor Rule 35).
- **Times are `America/Chicago`**, through `formatLocal`.

## Screen Inventory & Layout Patterns

### 0. Navigation — no new destination

**The run report does not get a nav tab or a sidebar row, deliberately.** 03-UI-SPEC § 0 fixed the phone tab bar at four (Presets · Review · Businesses · More). Four is the most that keeps every label real text at 390px. A run is a child of a preset, reached from that preset or from `/spend`. It is not a place danlo goes to on its own.

- **Route: `/runs/[id]`** *(default — danlo may override in CONTEXT.md)*. `[id]` is the internal run uuid, guarded by `src/lib/ids.ts`. The existing `tests/unit/ids.test.ts` walk finds it automatically, because it discovers every `[id]` route.
- **Which nav item is lit:** **Presets.** `NavItem` gains an optional `alsoActiveUnder: readonly string[]`. `LEADS_NAV`'s Presets entry sets it to `['/runs']`, and `isNavActive` checks both. The inherited rule stays true: the user is never on a screen with no lit tab.
- **How it is reached:**
  1. Preset detail → "Recent runs" card rows (new);
  2. Preset detail → the summary card's last-run line → "Open the run report" (inline link);
  3. `/spend` → By run → each run's name (desk: the name cell is a link; phone: the whole card is a link);
  4. Immediately after confirming any run action, the drawer navigates to the new run's report.
- **Breadcrumb (desk):** Presets / {preset name} / Run {Sep 23, 2:14 PM}. **Phone:** a 44px back link "← {preset name}" above the title.

### 1. Run report — `/runs/[id]` (NEW; D-15, D-16, D-17; criteria 3 and 5)

**Purpose.** Answer four questions about one run, in this order: *Is it done? What did it cost against what we said it would? Did Google truncate anything? What did we find?* The tone is `/sources`: a ledger, read top to bottom and down the columns.

**Focal point:** **the header card's cost figure and status line, as one block.** That is the run's actual cost at Display 28/600 (foreground, tabular), directly beside the status badge and its one-line summary at Body 16/600. While the run is live, the status line carries the motion of the page. When it has stopped, the cost against the estimate is the verdict.

**What draws the eye first, in order:**
1. the status badge + summary line;
2. the cost figure;
3. the truncation warning, **if present** (a warning alert directly below the header is designed to interrupt);
4. the Tiles counts;
5. the Outcomes.

**Hierarchy:** page title → header card → [partial / refused / failed alert] → [truncation warning] → **Requests** → **Tiles** → **Outcomes** → footnote.

**Page title:** "Run report" (Heading 20/600). Beneath it, Label 14/400 muted: "{preset name} · version {n}". `document.title`: "Run report — {preset name}".

**Header card** (`data-testid="run-report-header"`):

```
[Running]  Full sweep · started Sep 23, 2:14 PM                ← badge (Label 14/600) + Label 14/400 muted
34 of 68 tiles searched so far                                  ← Body 16/600, tabular   (status summary)
$1.12                                                           ← Display 28/600, foreground, tabular
Estimated $1.90–$2.90 · this run stops at $5.80                 ← Label 14/400 muted, tabular
Updated 2:14:05 PM · updating every 5 seconds   [Refresh now]   ← Label 14/400 muted + outline button (44px)
```

- The tiles denominator is the **current** known tile count, which grows as tiles subdivide. That is why there is **no progress bar**: a bar whose total grows would move backwards. *(default — Open Question 16)*
- The status summary by state: `queued` → "Waiting to start"; `running` → "{n} of {m} tiles searched so far"; `complete` → "Complete — {m} tiles searched in {duration}"; `partial` → "Stopped early — {n} of {m} tiles searched"; `refused` → "Refused before any request"; `failed` → "Failed after {calls} requests".
- The ceiling line ("this run stops at $5.80") is always shown. It is **2 × estimate-high**, computed from the committed constant beside `FAN_OUT` (D-15), never hard-coded (inherited Executor Rule 16).
- **Above the estimate but below the ceiling:** a second muted line, "Above the estimate's top by $0.40 — still under this run's $5.80 stop." This is muted text, not warning: nothing has stopped.
- On a terminal status the "Updated …" line becomes "Finished Sep 23, 2:31 PM · took 17m 04s", and **"Refresh now" disappears** (nothing will change).
- Change-check runs render "$0.00" and the line "Change checks use the free IDs-only search — every request is still written to the ledger."

**Stop / refusal / failure alerts** (directly below the header, full width). Each is an `Alert`, the stopped reason always rendered through the copy map:

| Status · reason | Tone | Copy (the first sentence is Body 16/600, the rest Body 16/400) |
|---|---|---|
| `partial` · `budget_cap_reached` | Warning, `triangle-alert` | "Stopped at your {cap} monthly cap after {cost}. Siteless refused the next request before it left, so nothing past the cap was charged. The {n} tiles already searched are complete; the {m} not searched yet can run after the cap resets on {date}, or after you raise it." → "Raise the monthly cap" (admin) / "Ask an admin to raise the cap" · "Open spend view" |
| `partial` · `exceeded_estimate` | Warning, `triangle-alert` | "Stopped at twice the estimate. This run was estimated at {lo}–{hi}, and Siteless stops any run at 2× the top of its estimate — {ceiling} — so a tiling surprise can't eat the month. {k} tiles were still subdividing when it stopped; they're listed below. Everything collected before the stop is complete." → "Show the tiles still subdividing" (toggles the list below) |
| `refused` · `budget_cap_reached` | Destructive, `octagon-x` | Inherited `RUN_REFUSED`: "This run was refused. Your {cap} cap is spent, so Siteless didn't call anything and nothing was charged." → "Raise the monthly cap" / "Ask an admin to raise the cap" |
| `failed` | Destructive, `octagon-x` | "The run failed after {calls} requests: {error}. Every request that left was reserved and ledgered first, so {cost} above is exactly what it cost. Start the run again from its preset; the tiles it reached are listed below." → "Open {preset name}" |

> "Google returns at most 60 places per search, and these tiles returned 60 even after Siteless split them as far as it's allowed to. Places beyond the 60th in them are missing from this run. **Live refresh contract (D-17):**
- **Mechanism:** a client island `RunAutoRefresh` (no data of its own) calls `router.refresh()`, so the server component re-renders from the database. No client-side data cache, no SSE, no Workflow stream subscription. *(default — Open Question 2)*
- **Cadence:** every **5 seconds** while `status ∈ {queued, running}`.
- **Stops** on any terminal status (`complete`, `partial`, `refused`, `failed`), after one final refresh.
- **Pauses** while `document.visibilityState === 'hidden'`. On becoming visible it refreshes **immediately**, then resumes the 5-second cadence.
- **Never blanks:** `router.refresh()` keeps the current tree until the new one arrives. No skeleton or spinner replaces a number during a refresh (inherited Executor Rule 11).
- **Failure:** a refresh that throws or times out after 10 seconds keeps the previous numbers. It shows the refresh-failed line (§ Copy Table) in place of "Updated …", then retries on the next tick.
- **"Refresh now"** triggers an immediate refresh and resets the 5-second timer. While a refresh is in flight the button shows `Spinner` + "Refreshing…" at the same width.

**Desk:** single column, max 1120px, cards at 24px gap, 24px inner padding. The four-count grids are `grid-cols-4`. **Phone:** single column, cards at 16px gap, 16px padding, every table becomes label/value rows. There is no sticky action bar: the screen has no primary action.

**Components:** `card`, `badge`, `alert`, `button`, `table`, `item`, `separator`, `collapsible`, `breadcrumb`, `skeleton`, `spinner`, `empty`, `progress` (optional share bars only). All installed.

### 3. Review queue — `/review` (D-05, D-07, D-08; Phase 3 screen, extended)

**Purpose.** The same 80–95 queue, now with **two item kinds**:
- **duplicate pairs** (Phase 3, unchanged);
- **tentative Google listings**: a listing scored 80–95 against a spine business, or tied at 95 or above across two businesses (D-08).

**Decision: one queue, with a filter.** *(default — Open Question 3)*
- Both kinds stay in **one score-ordered queue** with one remaining count and one "Queue clear" end state. That keeps 03-UI-SPEC's end-state contract, which TRI-03 reuses in Phase 7.
- A **filter** lets danlo batch one kind at a time. Google items usually mean opening Google Maps in another app, and batching them avoids switching context on every other item.
- The filter is a `ToggleGroup` (single-select, full width on phone, 44px) directly under the page title: **All · Duplicates · Google** (`review-filter-all|duplicates|google`). - The visible label is "Google". Its accessible name is "Google listings".

Inherited wholesale from `02-UI-SPEC.md` and `03-UI-SPEC.md` § Accessibility & Touch. Phase 4 adds:

  - the filter toggles are 44px;

- **Thumb zone.** Nothing irreversible commits from the thumb bar. "Not this business" only opens a confirmation. "Same business" is reversible through Detach.
- **The run report's live region: polite, and quiet.**
  - One visually hidden `role="status"` `aria-live="polite"` `aria-atomic="true"` region (`run-live-status`) announces **only transitions**: the status changing (queued → running → terminal), and the first appearance of a truncation warning. See the "Live announcement" copy.

  - The truncation `Alert` carries `role="status"` (warning, not `role="alert"`: nothing needs an interrupt).

## Motion

`motion@13.4.0` is in the stack. **Phase 4 adds no animation.**

| Surface | Motion |
|---------|--------|
| Run report refresh | **None.** Values swap in place. No count-up, no flash, no highlight of changed numbers, no layout shift (tabular numerals and fixed grid columns). |
| Running badge spinner | The shadcn `Spinner`'s `animate-spin`, with **`motion-reduce:animate-none`**. Under reduced motion it renders as a static glyph; the word "Running" carries the state either way. |
| Queue advance (Google item) | Inherited `ReviewAdvance`, 150ms, reduced-motion handled as shipped. |
| Collapsibles (truncated tiles, check history, still-subdividing tiles) | Radix's own height transition, not wrapped in `motion` (inherited rule: one animation system per element). |
| Dialogs, drawers | Radix / vaul springs (inherited). |

**`prefers-reduced-motion`:** *disable the animation, never the content* (inherited, recorded 956 Woodworks defect). There is no code path in which a reduced-motion user sees a blank count, an empty report region or a missing warning. The run report has no motion to reduce beyond the spinner, and that is by design.
