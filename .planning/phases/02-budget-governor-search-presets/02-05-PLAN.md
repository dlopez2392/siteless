One custom migration (`db:custom --name=budget_meter_functions`), five functions, `--> statement-breakpoint` between every statement and **each function body kept as ONE statement** — a naive splitter otherwise cuts a `$$ ... $$` body on its first internal semicolon.

🔴 Every one is `security definer` with `set search_path = public` **pinned on the same statement** (ASVS V4: a definer function whose search_path is attacker-influenced runs as the owner). Every one ends with an explicit `grant execute on function app.<name>(<types>) to authenticated;`. **None takes `org_id` or `actor_id` as a parameter** — they resolve the caller from the transaction-local claims themselves, exactly as `app.emit_event` does.

**1. `app.current_org_role() returns text`** — `language sql stable`. Verbatim from RESEARCH:
```
select coalesce(app.jwt()->'o'->>'rol',
                nullif(replace(coalesce(app.jwt()->>'org_role',''), 'org:', ''), ''))
```
Comment it: Clerk session token v2 nests the **bare** role under `o.rol` (`'admin'`), while v1 carries the **prefixed** form flat (`'org:admin'`) and `@clerk/shared` builds `auth().orgRole` as `` `org:${o.rol}` ``. A naive coalesce compares `'admin'` to `'org:admin'` and the admin gate silently passes or silently fails depending on which side you wrote first. Normalise to the BARE form in SQL; the TypeScript side uses the prefixed one. This is the exact sibling of Phase 1's D-11 highest-probability silent failure, and both shapes get their own test in plan 02-08.

**2. `app.ensure_budget_period(p_provider text, p_period date) returns uuid`** — `language plpgsql`. Get-or-create in `drizzle/0009`'s select-then-do-nothing shape: resolve `v_org := app.current_org_id()` and raise `42501` if null; refuse a provider outside `('places','firecrawl','anthropic')` with `22023`; `select id ... where org_id/provider/period_start` and return it if found; otherwise select the **most recent earlier period's `cap_micro_usd` for the same (org, provider)** into `v_cap`, `insert ... values (v_org, p_provider, p_period, coalesce(v_cap, 50000000::bigint)) on conflict (org_id, provider, period_start) do nothing returning id into v_id`, and if `v_id is null` (lost the race) re-select. Carrying the previous cap forward is what makes an edited cap persist across months.

**3. `app.reserve_budget(p_provider text, p_period date, p_micro bigint, p_run uuid, p_sku text, p_ttl interval default '10 minutes')`** — `returns table (reservation_id uuid, pct_after numeric, at_80 boolean, at_100 boolean)`, `language plpgsql`. Paste RESEARCH's verified body, in this order:
  - resolve `v_org`; `42501` if null; `22023` if `p_micro <= 0`
  - call `app.ensure_budget_period(p_provider, p_period)` first, so a caller never has to
  - **self-heal** (Pattern 2): the `with expired as (... for update of r skip locked), rel as (update cost_reservations r set released_at = now() from expired e where r.id = e.id returning e.est_micro_usd) select coalesce(sum(est_micro_usd),0) into v_freed from rel;` block, then decrement `reserved_micro_usd` by `v_freed` if positive. `skip locked` means a concurrent healer releasing the same row is left alone. This is what takes the sweeper off the correctness path entirely.
  - **the meter** (Pattern 1) — 🔴 **ONE statement, and no SELECT of a budget total before it**:
    `update budget_periods set reserved_micro_usd = reserved_micro_usd + p_micro where org_id = v_org and provider = p_provider and period_start = p_period and spent_micro_usd + reserved_micro_usd + p_micro <= cap_micro_usd returning id, reserved_micro_usd, spent_micro_usd, cap_micro_usd into v_bp, v_r, v_s, v_c;`
    PostgreSQL READ COMMITTED re-evaluates that WHERE clause against the committed new version of a row it had to wait for; that is the whole proof. Gate mutation M7 replaces this with a SELECT-then-UPDATE and must red only the concurrency test.
  - **denial is zero rows, not an exception.** If `v_bp is null`, re-read the row for reporting and `return query select null::uuid, round(100.0*(v_s+v_r)/v_c, 1), (v_s+v_r)*100 >= v_c*80, (v_s+v_r) >= v_c; return;`
  - on success, `insert into cost_reservations (org_id, budget_period_id, run_id, sku, est_micro_usd, expires_at) values (v_org, v_bp, p_run, p_sku, p_micro, now() + p_ttl) returning id into v_res;`
  - **the 80% crossing, decided from the SAME row version** (Pattern 3) and emitted **once per period**: if `at_80` is true, `update budget_periods set warned_80_at = now() where id = v_bp and warned_80_at is null` and only if that updated a row, `perform app.emit_event('budget_periods', v_bp, 'budget_80_percent', jsonb_build_object('pct_after', v_pct, 'provider', p_provider, 'period_start', p_period));` 🔴 Through `app.emit_event`, never a direct insert: `authenticated` holds no INSERT on `events` and `emit_event` takes neither org nor actor, so attribution cannot be forged.
  - 🔴 Prefer `(v_s+v_r)*100 >= v_c*80` over `v_c*80/100`, and make sure every literal rides a `bigint` column or carries `::bigint`.
  - 🔴 PostgreSQL 17 compatible only: no `returning old.` / `returning new.`, no `uuidv7(`, no virtual generated columns.

**4. `app.settle_reservation(p_reservation uuid, p_request_id text, p_actual_micro bigint, p_units integer, p_sku text, p_provider text, p_lead uuid default null) returns boolean`** — `language plpgsql`, Pattern 4. Load the reservation and its `est_micro_usd`/`budget_period_id`/`run_id`/`org_id` (as the definer, bypassing RLS, after checking the reservation's `org_id` equals `app.current_org_id()` and raising `42501` otherwise). Then:
  `insert into cost_ledger (org_id, budget_period_id, reservation_id, run_id, lead_id, provider, sku, units, micro_usd, request_id) values (...) on conflict (request_id) do nothing; get diagnostics v_ins = row_count; if v_ins = 0 then return false; end if;`
  then `update cost_reservations set settled_at = now() where id = p_reservation and settled_at is null;`
  then `update budget_periods set reserved_micro_usd = reserved_micro_usd - v_est, spent_micro_usd = spent_micro_usd + p_actual_micro where id = v_period;` and `return true`.
  🔴 **Reserve the worst case, settle the actual.** Reserving one page and discovering three is the only way to breach the cap. The true-up returns the difference. `p_actual_micro = 0` is legitimate and required: the ledger records **every paid-SKU call including zero-cost ones**, or the monthly free allowance is untrackable and every early-month estimate is wrong.

**5. `app.set_budget_cap(p_provider text, p_cap_micro bigint) returns bigint`** — `language plpgsql`, in `drizzle/0004`'s claim-check-then-write shape. Note in a comment that this floor is **tighter** than the UI-SPEC's copy ("at least {spent + $1}"): the true floor is `spent + reserved`.
  Derive the current Chicago period inside the function as `(date_trunc('month', now() at time zone 'America/Chicago'))::date` — CONVENTIONS section Time forbids a bare `::date`, which silently buckets in UTC.
