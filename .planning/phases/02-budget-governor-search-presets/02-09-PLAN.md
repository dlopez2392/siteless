**`src/server/actions/_result.ts`** — one discriminated union every action returns, so the UI never has to distinguish an expected refusal from a crash:
```
export type ActionResult<T> =
  | { ok: true; data: T }
  | { ok: false; code: 'unauthorized' | 'forbidden' | 'not_found' | 'conflict'
              | 'budget_refused' | 'validation' | 'upstream' | 'unexpected';
      message: string; detail?: Record<string, string | number> };
```
🔴 An expected refusal — the cap is spent, the version moved, the geocoder found nothing — is a RESULT, never a thrown exception. Only a genuine bug throws.

**`src/server/actions/queue-run.ts`** — `'use server'`, `requireOrg()` first. This is the orchestrator's settled decision: **"Run this preset" ships live** — it creates a `runs` row in status `queued` and TAKES the budget reservation, so success criterion 5's refusal at 100% is reachable from the UI and not only from a test. Phase 4 consumes `queued` runs.
```
export async function queueRun(input: { searchVersionId: string }):
  Promise<ActionResult<{ runId: string; reservationId: string; pctAfter: number; at80: boolean }>>
```
Inside ONE `withOrg` transaction:
  1. read the version (RLS confines it; not found -> `code:'not_found'`)
  2. compute the estimate for that version's spec and take `costMicroUsdHi` as the reservation amount — 🔴 **reserve the worst case, settle the actual.** Reserving one page and discovering three is the only way to breach the cap.
  3. `insert into runs (org_id, search_version_id, status) values (app.current_org_id(), $1, 'queued') returning id`
  4. `select * from app.reserve_budget('places', $period, $microHi, $runId, 'ts_enterprise')` where `$period` is `periodStart(new Date())` from `src/lib/budget/period.ts`
  5. 🔴 if `reservation_id` is **null** the cap is reached: set the run to `status = 'refused'` with `stopped_reason = 'budget_cap_reached'` and return `{ ok:false, code:'budget_refused', message: RUN_REFUSED(formatUsd(cap)), detail:{ pctAfter } }`. **A denial is zero rows, not an exception** — there is nothing to catch, and treating it as one is how this becomes a 500 instead of a sentence.
  6. otherwise return `ok:true` with `pctAfter` and `at80` so the caller can surface the 80% state immediately. An UNTAKEN reservation expires by TTL and the self-healing reserve releases it — no cleanup code here.
  7. `revalidatePath('/spend')` and the preset path.
Include the UI-SPEC Phase-4 notice constant in the returned data or let the component read `PHASE4_RUN_NOTICE` directly — the drawer copy must say runs execute when the Places verifier ships in Phase 4.
