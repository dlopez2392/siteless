**`summary-card.tsx`** — a `Version 3 · current` badge, the cluster list, the geography, the inline single-line estimate, and `Last run Sep 18, 2:14 PM · $2.31`. The inline estimate uses the single-line form: `~68 requests · ~$2.40 · ~1,100 businesses · 4.8% of this month's remaining $47.60`. 🔴 Executor Rule 16: those are FORMAT, not arithmetic — every figure comes from the server-computed `EstimateRange` for the current version, with the free allowance already applied, so an early-month preset genuinely reads `$0.00`. Money through `formatUsd`, percentages through `formatPct`, dates through `formatLocal`, everything comparable `tabular-nums`.

**`version-diff.ts`** — PURE, no I/O, no `"use client"`. `describeVersionDiff(prev, next): string[]` returning concrete clauses joined by ` · ` in the UI:
  - added and removed clusters, by display name: `Added Auto & retail`, `Removed Food & hospitality`
  - a geography-kind change: `Geography changed from County to Cities`
  - within the same kind, added and removed units by name: `Added Starr County`, `Removed South Padre Island`
  - a radius change: `Radius 10 mi → 25 mi`, `Centre moved to 101 N BRITTON AVE, RIO GRANDE CITY, TX, 78582`
  - `Version 1` (no previous) returns `['Created']`
🔴 Never a hash, never "changed". UI-SPEC is explicit that "What changed" is a concrete diff sentence.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `queueRun` | The only UI path in this phase that can cause a budget reservation |
| preset id / version id in the URL -> a tenant's data | An id is guessable; RLS is what makes guessing useless |
| a refusal -> the person who caused it | A refusal that disappears is a refusal that gets retried blindly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan | Severity |
|-----------|----------|-----------|-------------|-----------------|----------|
| T-2-04 | Tampering | reservation from the UI | mitigate | The drawer calls `queueRun`, which goes through `app.reserve_budget`'s single conditional UPDATE; the UI has no other path to a reservation and cannot compute or submit an amount of its own. Task 2. | high |
| T-2-10 | Information Disclosure | preset or version by id | mitigate | `getPreset` reads through `withOrg`, so a foreign id is simply not found and the page renders `notFound()` rather than confirming the resource exists. Task 1. | high |
| T-2-12 | Tampering | a run re-pointed at another version | mitigate | The UI never sends `search_version_id` on an update; `runs.search_version_id` is outside the column grant (plan 02-03) and the e2e spec asserts the older version keeps its run count after an edit. Tasks 1-2. | high |
| T-2-02 | Elevation of Privilege | "Raise the monthly cap" in the refusal | mitigate | The admin action renders only for `auth().orgRole === 'org:admin'`; a member gets "Ask an admin to raise the cap". Affordance only — the boundary is `app.set_budget_cap` plus the absent UPDATE grant. Task 2. | medium |
| D-12 (no STRIDE ref) | Repudiation | refusal visibility | mitigate | The refused reservation is a persistent destructive `Alert` inside the drawer, never a toast, and it states explicitly that nothing was charged. A criterion checks the toast is on the success branch only. Task 2. | high |
</threat_model>
