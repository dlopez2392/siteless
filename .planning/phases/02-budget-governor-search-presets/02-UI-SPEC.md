# Phase 02 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This is the phase where the design system is born.** Phase 1 shipped an unstyled shell on purpose (see the comment in `src/app/layout.tsx`). Everything below is the contract for Phases 2 through 9 — the triage card stack (Phase 7), the receipts timeline (Phase 5), the spend/false-positive dashboard (Phase 9) inherit these tokens, these layout patterns and these rules without re-deciding any of them.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, chip inner padding, gap between a number and its unit |
| sm | 8px | Compact element spacing, gap between form control and its help text, badge padding |
| md | 16px | Default element spacing, card inner padding on phone, screen gutter on phone |
| lg | 24px | Card inner padding on desk, gap between cards, form field vertical rhythm |
| xl | 32px | Screen gutter on desk, gap between a section heading and its content |
| 2xl | 48px | Major section breaks, empty-state vertical padding |
| 3xl | 64px | Page-level spacing, top app bar height, bottom tab bar height, sidebar footer offset |

**Exceptions** (each justified, each deliberate):

| Value | Where | Justification |
|-------|-------|---------------|
| 44px | Minimum hit area (width **and** height) of every interactive element on phone | MOB-01 thumb-zone requirement + WCAG 2.2 AA target size. Where the *visual* control is smaller (a 24px icon button), the hit area is expanded with padding or an `::after` overlay to 44×44 — the visual box stays on the scale. |
| 1px | Borders, table row dividers, sidebar edge | Hairline; not a layout dimension. |
| 2px | Focus ring width, active-nav indicator thickness | Hairline; not a layout dimension. |
| `env(safe-area-inset-bottom)` | Padding added *below* the 64px bottom tab bar and below the sticky phone action bar | Dynamic OS value on installed iOS PWAs. Added to, never substituted for, the 64px. |
| 256px | Desk sidebar width | A fixed panel width, not a spacing step; `16 × 16`. |
| 320px | Desk estimate rail width (preset editor) | A fixed panel width; `16 × 20`. |
| 1120px | Max content width on desk | Reading-measure cap, not a spacing step. |

No other value is permitted. `12px`, `20px`, `36px` and friends are **not** in this system — if a gap feels wrong at 8 and wrong at 16, change the type size or the border, not the scale.

## Typography

One family: **Inter**, variable, loaded with `next/font/google`, `subsets: ['latin']`, `display: 'swap'`, `variable: '--font-sans'`. Fallback stack (painted into `@theme`, not left to the browser):

```
ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, "Noto Sans", sans-serif
```

**Exactly 4 sizes. Exactly 2 weights.** Nothing else ships.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 (24px) |
| Label | 14px | 400 | 1.43 (20px) |
| Heading | 20px | 600 | 1.3 (26px) |
| Display | 28px | 600 | 1.2 (34px) |

Weights: **400 Regular** and **600 SemiBold**. No 300, no 500, no 700.

Role assignment (so nobody invents a fifth size):

- **Display 28/600** — the live estimate's dollar figure; the month-to-date spend figure on `/spend`; the cap figure on `/settings/budget`. Nothing else. These are the numbers that *are* the product.
- **Heading 20/600** — page title, card title, preset name, drawer/dialog title, empty-state heading.
- **Body 16/400** — all prose, all form inputs (16px is also what stops iOS from zooming the viewport on focus), button labels on phone, empty-state body, error body.
- **Body 16/600** — a number inside body flow (a preset card's cost, a table's money cell), and the one-line summary of a banner.
- **Label 14/400** — muted metadata, table cells, table headers, helper text, timestamps, the non-dollar segments of the estimate line, bottom-tab labels.
- **Label 14/600** — form labels, table column headers, badge text, section eyebrows.

**Numerals — non-negotiable on this phase's screens:**

- Every number that is compared, summed, or changes in place gets `tabular-nums` (Tailwind v4 `tabular-nums` utility → `font-variant-numeric: tabular-nums`). That is: dollars, cents, request counts, business counts, percentages, version numbers, run counts, dates in tables.
- Money columns in any `Table` are **right-aligned** on desk (`text-right`), left-aligned in the phone card fallback with the label on the left and the value on the right of a flex row.
- Money is formatted with `Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' })` and always shows cents (`$47.60`, never `$47.6`, never `$48`). Percentages show one decimal (`4.8%`).
- A recomputing estimate **never** collapses to a skeleton — see *States → Loading*.

### Accent reserved for — exhaustive list

Accent (`#0F766E` / `#2DD4BF`) appears **only** on:

1. The **one** primary CTA on a screen (filled button). One per screen; a second filled accent button on the same screen is a spec violation.
2. The **active** item in the desk sidebar and in the phone bottom tab bar — accent label + accent icon + a 2px accent indicator (left edge on desk, top edge on phone).
3. The **focus ring** on every focusable element (2px, 2px offset, `:focus-visible`).
4. The **dollar figure** in the live estimate line on the preset editor, and the **month-to-date spend figure** on `/spend`.
5. The **budget gauge fill** while spend is under 80% of the cap.
6. **Inline text links** inside body copy ("How this is estimated", "Read the compliance note", "Open spend view").
7. The **`Current` version badge** on the preset detail page — accent outline and accent text, no fill. The only badge that carries accent.

Accent does **not** appear on: secondary or ghost buttons, inactive nav items, card borders, table headers, badges other than the active-version badge, icons that are not the active nav item, hover states of non-primary controls, or "all interactive elements".

### Destructive / warning reserved for

- **Destructive** — the 100% cap-reached banner and its badge, the disabled-run refusal message, inline field validation errors, the `failed` and `refused` run badges. **There are no destructive actions in this phase** (preset archiving, deletion and unmerge are all deferred per `02-CONTEXT.md` § Deferred Ideas), so there is no destructive button and no destructive confirmation dialog in Phase 2. The colour still ships because the refusal state and validation errors need it.
- **Warning** — the persistent 80% banner, the gauge fill between 80% and 99.9%, and the `partial` run badge. Nothing else.

**Colour is never the only signal.** Every threshold state also carries an icon (`triangle-alert` at 80%, `octagon-x` at 100%) and a text label. The gauge always renders its numeric label beside it.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Create preset"** (list header) / **"Create your first preset"** (empty state) / **"Save as version {n}"** (editing) / **"Run this preset"** (preset detail) / **"Save monthly cap"** (budget settings) |
| Empty state heading | **"No search presets yet"** |
| Empty state body | "A preset is one or more industry clusters crossed with a geography — the 17 RGV cities, a county, or a radius around an address. Siteless costs it before it runs, so you always know what a search will spend." → CTA "Create your first preset" |
| Error state | **"We couldn't find “{address}”."** — "The US Census Geocoder matches street addresses, not business names or PO boxes. Try a street address with a city and ZIP, or define this preset by county instead." → actions "Try another address" · "Switch to county" |
| Destructive confirmation | **None in this phase.** No preset can be deleted or archived (deferred), and raising or lowering the monthly cap is an audited, reversible edit, not a destructive action. The only refusal copy is the 100% cap state, which is a system refusal rather than a user-confirmed destruction: "Your $50.00 monthly cap is spent. Siteless refused this reservation, so nothing was charged. Raise the cap in Budget settings, or wait for the reset on {date} at 12:00 AM America/Chicago." |

Voice rules for every string on every screen in this project:

- **Name the number.** "Your $50.00 monthly cap is spent" beats "Budget exceeded".
- **Say what happened to the money.** Any refusal or failure states explicitly that nothing was charged, when that is true.
- **Every error ends with a way out** — a button, a link, or a concrete instruction. Never a dead end.
- **No generic labels.** Never "Save", "Submit", "OK", "Cancel", "Delete", "Continue" on their own. The dismiss action in a drawer is "Keep editing" or "Close without saving", never "Cancel".
- **Times and dates are America/Chicago and say so** when they carry money consequences (the cap reset).

## Theme (light / dark)

Both palettes ship in this phase. Neither is an afterthought — the review screenshots are taken of the **real screens in both themes on the built app** (see *Executor Rules*).

- `next-themes@0.4.6` `ThemeProvider` wraps the app inside `ClerkProvider`, with `attribute="class"`, `defaultTheme="system"`, `enableSystem`, `disableTransitionOnChange`.
- `<html>` carries `suppressHydrationWarning` (required by next-themes) and the Inter font variable class.
- `src/app/globals.css` declares the light palette on `:root` and the dark palette on `.dark`, as **literal hex values** from the two tables above.
- Tailwind v4 `@theme inline { --color-background: var(--background); … }` maps them to utilities. This is Tailwind's build-time indirection and is fine.
- **Any token composed at runtime from another token** — e.g. a translucent ring built with `color-mix(in oklab, var(--primary) 30%, transparent)` — is declared on `*` and `.dark *`, **never on `:root`**. A composed custom property resolves where it is declared; declaring it on `:root` freezes the light value for the whole document (recorded BIS defect).
- `<meta name="theme-color">` ships per scheme: `#F4F6F7` light, `#0E1416` dark, so the installed PWA's status bar matches (this is what Phase 7's PWA inherits).
- `sonner`'s `<Toaster />` is mounted in the root layout with `theme` driven by `next-themes` and `position="bottom-center"` on phone / `"bottom-right"` on desk, offset above the bottom tab bar.
- Theme switching must not change layout: both palettes use identical spacing, radii and type.

### 3. Preset detail — `/presets/[id]`

**Focal point:** the current-version summary card with the estimate and the "Run this preset" CTA.

## Accessibility & Touch

- **Touch targets:** every interactive element is ≥44×44 CSS px on phone. Visual boxes smaller than that expand their hit area with padding or an `::after` overlay; the visual box stays on the spacing scale.
- **Thumb zone (MOB-01):** the single primary action on any phone screen sits in the sticky bottom action bar, above the tab bar. Nothing destructive and nothing irreversible sits there.
- **Focus:** `:focus-visible` gets a 2px accent ring with 2px offset on every focusable element. `outline: none` without a replacement ring is a defect. Focus order follows DOM order; drawers and dialogs trap focus and restore it to the trigger on close.
- **Names:** every control has an accessible name. Icon-only controls (the phone user-menu avatar, the remove-city `x`) carry `aria-label`; every *primary or navigational* control carries a **visible text label** — the bottom tab bar is icon-plus-label, never icon-only.
- **Contrast:** every pair in the colour tables is ≥4.5:1 for text and ≥3:1 for borders and meaningful icons, in both themes. Measured ratios are recorded in the colour tables; any new pair must be measured before it ships.
- **Colour is never the only signal:** threshold states carry an icon and a text label; run statuses carry a word, not just a tone.
- **Live regions:** the estimate region is `aria-live="polite"` + `aria-busy` while recomputing. The 80% banner is `role="status"`; the 100% banner is `role="alert"`.
- **Forms:** `Field` binds `Label` via `htmlFor`; errors are linked with `aria-describedby` and the control gets `aria-invalid`. Error text is never colour-only — it carries the `circle-alert` icon.
- **Inputs are 16px** so iOS Safari does not zoom the viewport on focus.
- **Numbers read correctly:** money uses `Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' })`; dates render in `America/Chicago` with the locale pinned (`en-US`) — zone *and* locale, per CLAUDE.md.
- **Reduced motion** is honoured everywhere (see *Motion*).
- **`data-testid` on every interactive element.** Convention: `{screen}-{element}-{qualifier}`, kebab-case, stable across copy changes — e.g. `presets-create-cta`, `preset-editor-estimate`, `preset-editor-estimate-dollars`, `preset-editor-mode-county`, `preset-editor-city-search`, `budget-cap-input`, `budget-cap-save`, `spend-mtd-figure`, `spend-gauge`, `spend-tab-by-run`, `budget-banner-80`, `budget-banner-100`, `run-confirm`, `version-row-2-run`, `version-row-2-duplicate`, `nav-presets`, `nav-spend`, `nav-settings`, `theme-switch`.

## Motion

`motion@13.4.0` is in the stack. In this phase it does four small jobs and nothing else — this is a governor screen, not a showcase.

| Animation | Spec |
|-----------|------|
| Estimate value change | 150ms: opacity 0.6 → 1 with a 2px upward translate on the dollar figure. The old value is never removed before the new one paints. |
| Budget gauge fill | 300ms `ease-out` width transition when the percentage changes. |
| Banner appearance (80% / 100%) | 200ms height + opacity on first mount only; it does not re-animate on navigation. |
| Drawer / sheet / dialog | vaul's and Radix's own springs. Do **not** wrap them in `motion` — two animation systems on one element is how a drawer ends up fighting itself. |

Toast entry/exit is `sonner`'s default.

**`prefers-reduced-motion` (recorded 956 Woodworks defect: a naive reduced-motion rule blanked the hero):**

- Use `useReducedMotion()` from `motion` and the `@media (prefers-reduced-motion: reduce)` query.
- When reduced: **disable the animation, never the content.** Durations go to 0, transforms are dropped, the element renders at its final state immediately. There is no code path in which a reduced-motion user sees an empty gauge, an empty estimate, or a missing banner.
- The gauge still renders at the correct width; the estimate still shows the new number; the banner still appears.

## Executor Rules

These are recorded defects from BIS, Cobija and 956 Woodworks. Each one cost a production bug. They are contract, not advice.

1. **Tailwind v4 arbitrary values use `[var(--x)]`, never `[--x]`.** v4 dropped the shorthand and emits invalid CSS *silently* — nothing fails, the style just does not exist.
2. **Painted values, never CSS custom properties, for anything a test pins.** `globals.css` holds literal hex values. An e2e or unit probe asserts the **computed value** (`expect(color).toBe("rgb(15, 118, 110)")`), never a variable name and never `.includes(...)`.
3. **Brand-composed custom properties go on `*` and `.dark *`, not `:root`.** Anything built with `var()` of another token resolves where it is declared; on `:root` it freezes one theme's value for the whole document.
4. **Write unprefixed CSS only.** Never hand-write a `-webkit-` twin — Lightning CSS replaces the standard property when a hand-written prefixed twin sits behind it, and the standard one silently disappears. Pin the computed *value* in any probe.
5. **A `"use client"` module's exports are client references inside a server component** — even plain data objects, which resolve to `undefined` at runtime with typecheck, lint and build all green. Keep label maps, tone maps and copy constants in server-safe modules (`src/lib/ui/run-tone.ts`, `src/lib/ui/copy.ts` — no `"use client"` at the top).
6. **No hand-rolled surfaces.** Every card, sheet, drawer, popover, input and badge on every screen is the shared shadcn primitive. A treatment applied only to the shared `Card` while 25 hand-rolled `bg-card` divs sit beside it reaches almost nothing, and every review passes because the tests pin the `Card`. Grep for `bg-card`, `rounded-`, `border border-` on raw `div`s before calling a screen done.
7. **Every interactive element gets a `data-testid`** following the convention above. When a screen is restyled or a route moves, **grep `tests/e2e/` for every testid and class the change retires** — a retired hook fails silently. Phase 1's `signed-in-as` / `org-id` / `org-row-id` move to `/settings/organization` and their spec moves with them, in the same task.
8. **Review screenshots are of the REAL screens, in BOTH themes, on the built app** (`next build && next start`, then Playwright) — never a styleguide page, never dev mode. Probe `getComputedStyle` to prove a visual change actually shipped. A hidden or zero-height Chrome window makes every measurement lie: assert `innerHeight > 0` and visibility first.
9. **Touch targets ≥44px on phone** — a declared spacing exception, enforced by a Playwright check over the primary controls on each screen at a 390×844 viewport.
10. **One accent action per screen.** If a screen seems to need two, one of them is secondary.
11. **Never blank content to satisfy a state.** Not for loading (the estimate dims, it does not disappear), not for reduced motion, not for an error (the previous value stays until a new one exists).
12. **Pin the toolchain after `shadcn init`.** `init` installs floating versions; STACK.md's pins win. Use the pnpm store launcher, never bare `pnpm`.
13. **`tailwind.config` stays empty.** Tailwind v4 is configured in `globals.css` with `@theme`; no `tailwind.config.ts` is created.
14. **This phase's UI must not depend on the Google Cloud key existing.** The quota card is a human-action checkpoint, not a live integration; nothing on any screen reads a Google credential.
15. **After `shadcn init`, the font is Inter, not the preset's Geist.** The `nova` preset binds `font: geist` and `init` writes that import into `layout.tsx`; swap it for Inter (`variable: '--font-sans'`) in the same task and never add a `geist` package (Components § Step 1b).
16. **The estimate figures in this document are illustrative copy, not arithmetic.** `×38 vs RGV`, `~68 requests · ~$2.40` and `4.8% of … $47.60` show the *format*. The Texas multiplier is **computed** as `estimate(texas).requestsHi / estimate(rgvBaseline).requestsHi` and rendered as `×{computed}` (02-RESEARCH.md § The Estimator measures ≈15× by cells); the dollar figure **applies the monthly free allowance** (the first 1,000 Text Search Enterprise requests each calendar month are free, so an early-month preset reads `$0.00`); and the ledger records **every paid-SKU call, including zero-cost ones** (`micro_usd = 0`, `units` set) or the free allowance cannot be tracked. Never hard-code any of these numbers.
