```
                | 'pd_essentials' | 'pd_pro' | 'pd_enterprise';

```
`freePerMonth: null` means unlimited (Text Search Essentials / IDs-Only is free without limit). Source, recorded as a comment above the table: `developers.google.com/maps/billing-and-pricing/pricing`, fetched 2026-09-22.

Also export:
```
export function priceRequests(sku: Sku, requests: number, freeRemaining: number):
  { billable: number; microUsd: number };
```
`billable = Math.max(0, requests - Math.max(0, freeRemaining))`, `microUsd = billable * PRICE_BOOK[sku].microUsdPerRequest`. Refuse a negative or non-integer `requests` by throwing with the value named. 🔴 **The free allowance is not optional.** A preset priced at 68 Enterprise requests costs `$0.00` on the 2nd of the month and `$2.38` once the first 1,000 are gone; quoting `$2.38` early in the month is wrong in the direction that makes danlo distrust the number, which is the whole product.

```
export function freeRemaining(sku: Sku, unitsUsedThisPeriod: number): number;
```
`freePerMonth === null` returns `Number.POSITIVE_INFINITY`; otherwise `Math.max(0, freePerMonth - unitsUsedThisPeriod)`. The ledger records **every paid-SKU call including zero-cost ones** (`micro_usd = 0`, `units` set), which is the only reason `unitsUsedThisPeriod` is derivable at all.

**`src/lib/budget/money.ts`** — pure, no I/O, no `"use client"`:
```
export const MICRO_PER_USD = 1_000_000;
export const MICRO_PER_CENT = 10_000;
export function microToCents(microUsd: bigint | number): number;   // 35000 -> 3.5
export function formatUsd(microUsd: bigint | number): string;      // 35000 -> "$0.04"? NO - see below
export function formatPct(fraction: number): string;               // 0.048 -> "4.8%"
export function parseUsdToMicro(input: string): bigint;            // "50.00" -> 50000000n
```
🔴 `formatUsd` uses `new Intl.NumberFormat(APP_LOCALE, { style: 'currency', currency: 'USD' })` with `APP_LOCALE` **imported from `src/lib/time.ts`** — never a second `'en-US'` literal in `src/`. An unpinned locale is an SSR hydration mismatch (recorded BIS defect for `es-*`). It always shows cents: `$47.60`, never `$47.6`, never `$48`. It formats the DOLLAR value, i.e. `microUsd / 1_000_000`, so `49_980_000` renders `$49.98` and `35_000` renders `$0.04` when rounded to two decimals — that rounding is a DISPLAY concern only and never feeds back into arithmetic.
`formatPct` shows exactly one decimal (`4.8%`), matching UI-SPEC section Typography.
`parseUsdToMicro` is what the budget-settings cap input goes through server-side: accept `50`, `50.0`, `50.00`, `$50.00`, `1,250.00`; reject empty, `NaN`, negative, more than two decimal places, and anything above `1_000_000_000_000n` micro-USD; throw naming the offending input. Never use a float intermediate for the micro conversion — parse the integer and fractional parts as strings and compose the `bigint`.

**`src/lib/budget/period.ts`** — built ON `src/lib/time.ts`, importing `APP_TZ`; it must not redeclare the zone string:
```
export function periodStart(instant: Date, timeZone?: string): string;      // 'YYYY-MM-01'
export function nextPeriodStart(instant: Date, timeZone?: string): string;  // 'YYYY-MM-01'
export function periodLabel(instant: Date): string;                         // 'September 2026'
export function periodResetInstant(periodStartIso: string): Date;           // the UTC instant of local midnight on the 1st of the NEXT month
```
`timeZone` defaults to `APP_TZ` so forgetting it is still correct, and exists as a parameter for exactly one reason: it is what makes the discriminating pair expressible. Derive the year and month with `Intl.DateTimeFormat(APP_LOCALE, { timeZone, year: 'numeric', month: '2-digit' }).formatToParts` — the same `formatToParts` approach `localDate` uses, and for the same reason (`en-US`'s own date order is M/D/Y and re-parsing a formatted string back into ISO order breaks the moment the locale changes).
🔴 Never `new Date().getMonth()`. `Intl` formats in the SYSTEM zone while `Date.UTC` anchors UTC midnight, which renders the previous day across the Americas.

| field mask sent to Google -> the price recorded in the ledger | If the two are derived independently, the invoice and the ledger diverge silently and the cap is meaningless |

| dev machine zone (`America/Chicago`) -> deployed zone (UTC) | A month boundary computed in the process zone is right here and wrong in production |
