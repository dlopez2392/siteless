<objective>
Close the production-only authorization gap plan 01-10's side-by-side found: Supabase ships `alter default privileges ... grant all on tables to anon, authenticated, service_role` for schema `public`, so every table drizzle-kit created as `postgres` inherited ALL privileges for `anon` and `authenticated` — including TRUNCATE, which is exempt from row-level security. Proven on production inside rolled-back transactions: `truncate public.events` as `authenticated` succeeded; `truncate orgs, businesses, source_records, events cascade` succeeded as both `authenticated` and `anon`. Migration 0007's `revoke update, delete on events from authenticated` landed but never touched `anon` or TRUNCATE. This contradicts D-06 (events immutable by grant) and T-1-03 ("no deployed code can bypass RLS").

Purpose: make the grant surface a database property on both databases, make local reproduce the platform condition so dev and CI can ever see it again (D-09 parity), and stop future tables from inheriting the default.
Output: migration 0008 applied to local and production with side-by-side privilege counts recorded; a grants-audit test watched failing under the reproduced condition; CONVENTIONS.md § Grants.
</objective>
